# M8 第 3 段: ロジアナの連続ストリーミング 設計

## 1. ゴールと完了条件

ロジアナを止めずに PC へ流し続け、記録長をホストの保存先で決まる長さにする（成功基準: 16 ch @ ≥ 10 MS/s 連続、
変化点圧縮ではそれ以上）。ホストの一時的な停止（Windows の数 ms〜数百 ms の受け取りの遅れ）に耐える。

| 完了条件 | 検証 |
|---|---|
| 書き込みと読み出しを同時に行い、DDR3（ロジアナのリング 120 MB）を FIFO として使う | cocotb（la_deep_buffer: 書きながら読み、拍の順序と欠けの無さ） |
| 未読がリングに迫ったら書き込みを止めて OVERRUN を立てる（黙って欠けない） | cocotb |
| 実機で RAW 12.5 MS/s（25 MB/s）を 10 秒以上、欠けなく受け取る | HIL |

## 2. 構成

```
sys: la_front → la_encoder → 非同期 FIFO → mem: la_mem_writer（ストリーム時はトリガで止まらず書き続ける）
                                                 │ 書いた総数 w_total
mem: 読み出し制御（未読 = w_total − r_total > 0 なら最大 256 拍ずつ mem_reader に読ませる）
                                                 │
mem_port ← 調停（書き込みと読み出しが両方要求していれば交互）
mem_reader → 非同期 FIFO → sys: stream_unpack → USB のストリーム EP（既存の経路）
```

- **CSR** `la_deep.control.stream`（bit2）: run の 0→1 の時点で 1 ならストリーム。トリガは無視する（クロストリガの
  ロジアナのトリガも無視）。run を 0 にすると書き込みを止め、未読を出し切ってから終わる（`status.reading` が 0 に戻る）。
  `stream_beats`（RO）= ストリームで書いた拍の総数（32 ビット、折り返す）。
- **形式**: リングの拍そのまま（RAW = 8 サンプル、RLE = 4 レコード。既存の `decode_beats` / `decode_transitions` で
  逐次に復号できる。拍は 16 バイト単位で届く）。
- **溢れ**: 未読 > リング − 256 拍で書き込みを止めて `status.overrun` を立てる。ホストは受け取った分までが正しい。
- **イベント記録**（DAP）は書き込み側の経路を共有したまま同時に使える（イベントのリングは別）。

## 3. 判断

| 判断 | 理由 | 誤っていた場合のコスト |
|---|---|---|
| DDR3 を FIFO にする（直結ではない） | 直結だと手前の FIFO（8 KB = 20 MB/s で 0.4 ms）がホストの受け取りの遅れで溢れる | 中（作り直し） |
| 読み出しは既存の mem_reader を 256 拍ずつ繰り返し起動する | 試験済みの部品を使い、新しい状態機械を小さく保つ | 低 |
| 調停は交互（両方要求しているとき） | 帯域 500 MB/s に対して書き込み・読み出しとも ≤ 40 MB/s。どちらも飢えない | 低 |
| 溢れたら止める（上書きしない） | 上書きすると読み出し中の拍が壊れ、ホストが欠けに気づけない | 低 |

## 4. 結果（2026-10-16）

- 実機: RAW 12.5 MS/s（16 ch、25 MB/s）を 10 秒、251 MB を欠けなく受け取った（`test_la_stream_hw.py`）。RLE を VCD に
  少しずつ書く。成功基準「16 ch @ ≥ 10 MS/s 連続」を満たす。
- cocotb: ホストが 2 万周期止まっても欠け・重複なし、受け手が止まったままなら overrun で止まり、それまでは欠けない。
  通常の捕捉の直後にストリームを始めても正しい（開始時に未読のレジスタを 0 に戻す。当初は前の捕捉の総数の差が
  1 周期残り、溢れの誤判定と読み出しの暴走が起きた）。
- 読み出しの制御は、未読・拍数・次の番地を 1 周期ずつに分けた状態機械（mem 100 MHz のタイミングのため）。
- ホスト: `DeepAnalyzer.stream` / `LaStream.chunks`（拍単位の逐次受け取り）、`stream_to_vcd`（VCD を少しずつ書く）、
  CLI `fprobe la out.vcd --stream 秒`、MCP `la_stream`。受け取りは `stream_beats`（書いた総数）を見て届いている分だけ要求する。
- 制約: Python での RAW の復号は約 1250 万サンプル/秒なので、12.5 MS/s の RAW を VCD に書きながらは追いつかない
  （受け取りだけなら追いつく）。長時間の記録は RLE か、受け取ったバイト列をそのまま保存して後で復号する。
