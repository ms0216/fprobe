# 対象の FPGA の中を JTAG で観測する（MCU と同じ時刻で並べる）

2026-10-20。利用者との検討（ブレインストーミング）から。利用者が決めたことと、私の判断（「判断」と書く）を分けて書く。

## 1. 目的と、なぜ

組み込み機器には MCU だけでなく FPGA も載っている。fprobe は今、MCU の中（変数・スレッド・ブレークポイント・
サンプラ）と基板の線（ロジアナ）を共通の時刻で並べられるが、**FPGA の中の動き**が欠けている。
「MCU が FPGA のレジスタに書いた → FPGA の状態機械がこう動いた → 割り込みが返った」を 1 本の時間軸で見られれば、
MCU と FPGA のどちらの問題かの切り分けが速くなる（fprobe の最優先の目的「なぜ壊れたか」を見つける解析力）。

## 2. 前提（利用者）

- 対象は **開発済みの基板**。外とのつなぎは **JTAG だけ**（FPGA の中の信号を出す空きの端子は無い）。
- FPGA の中身（ビットストリーム）は作り直せる（観測の回路を入れてもらえる）。
- MCU は FPGA とは**別の口**。MCU は複数あり、JTAG のものも SWD のものもある。
- この機能は **PYNQ-Z2 のような大きい FPGA の fprobe だけに入れる**。小さい FPGA（Tang 系）には入れず、ケイパビリティで
  有無を申告する（CLAUDE.md の「機能はパラメータ・ケイパビリティで有効/無効、PC 側は申告を見て動く」）。
- 最初は **FPGA 1 個 + MCU 1 個** を同時に（判断。利用者に「難しくて分からない」と言われ、私が決めた）。口を増やせる作りにする。

## 3. ゴール・非ゴール・してはいけないこと

ゴール:
1. 対象の FPGA の内部の信号を、**途切れずに流し続けて**記録できる（変化の少ない状態・制御の信号。JTAG の帯域の範囲）。
2. 一瞬に込み合う信号（データのバス等）は、対象の FPGA の内蔵メモリに**全クロックで**記録し、後で読める（トリガの前後）。
3. FPGA の記録が **fprobe の時刻**に直り、MCU の出来事（DAP の転送・サンプラの値・ブレークポイント）・ロジアナと
   **同じ時間軸**に並ぶ（**追加の線なし**）。
4. 見る信号の組を、**対象の FPGA を作り直さずに**切り替えられる。
5. FPGA の中のレジスタを JTAG で読み書きできる（Xilinx の JTAG-to-AXI に当たる）。
6. PC・AI（MCP）から、fprobe の既存のロジアナ・記録と同じ形で使える（VCD・時間軸・解読器）。

非ゴール:
- Xilinx の ILA・Intel の SignalTap の通信の形式との互換（自前の形式）。
- バウンダリスキャン（設計を変えずに端子を読む。後の別の仕様）。
- 対象の FPGA の外部メモリ（DDR 等）を記録に使うこと（後で足せる口だけ残す）。
- 対象の FPGA の書き込み（コンフィグ）。観測の回路を入れたビットストリームを書くのは、利用者の普段の道具で。

してはいけないこと:
- Tang 系の構成（Primer・Nano）に影響を与える（資源・タイミング・ピン）。
- 対象の FPGA の JTAG を、観測の回路以外の目的で勝手に操作する（コンフィグ用の命令・EXTEST 等を出さない）。
- 観測の回路にベンダーの暗号化 IP を使う。

## 4. 全体の形

```
 PC（Python / MCP）
   │ 既存のホストリンク（PYNQ は UDP の中継）
 fprobe（PYNQ-Z2 の PL）
   ├─ 既存のデバッグの口（PMOD JA）── MCU（SWD / JTAG）       … 今のまま
   └─ 新しい「FPGA 観測の口」（JTAG の 4〜5 本）── 対象の FPGA の JTAG
        └─ obs_jtag_engine: JTAG を休まず回し、FIFO を吸い出して fprobe の記録へ。時刻合わせの命令。
 対象の FPGA
   └─ 観測の回路 fprobe_obs（利用者の設計に入れる）
        ├─ 信号の候補（多数）→ 選択器（JTAG で組を選ぶ）
        ├─ 流し続け: 変化の圧縮（時刻の差分 + 値）→ FIFO → JTAG の DR で吸い出し
        ├─ 内蔵メモリへの記録: トリガ・保存の条件・前後の深さ
        ├─ 時刻の数え（対象のクロック）と、Update-DR で写し取る時刻の窓
        ├─ バスの親（レジスタの読み書き。任意）
        └─ 申告（本数・深さ・組・版）
        └─ ベンダーの「設計から JTAG を使う部品」の包み（BSCANE2 / GW_JTAG / JTAGG / sld_virtual_jtag / UJTAG）
```

## 5. 対象の FPGA に入れる観測の回路（fprobe_obs）

- **ボード・ベンダー非依存の本体** + **ベンダーの JTAG の部品の包み**（CLAUDE.md の「ベンダー固有のプリミティブは
  ラッパ越しにのみ」）。本体の口は「ユーザーの DR」（TCK・TDI・TDO・Capture/Shift/Update・選択）だけ。
- **言語**: VHDL-2008（プロジェクトの規約）。利用者の設計が Verilog でも使えるよう、Verilog の包み（インスタンスの
  ひな形）も用意する（判断）。
- **ライセンス**: 利用者の製品の FPGA に入る回路なので、**Apache-2.0**（host/firmware・fprobe_tp.h と同じ扱い）にする
  （判断。gateware の GPL-3.0 だと製品に入れにくい）。利用者に確かめる。
- **流し続け**: 選んだ組（例: 最大 32 ビット）の値が変わった周期だけ「前の記録からの周期数 + 新しい値」を FIFO へ。
  周期数が長く空いたら時刻だけの記録を入れる。FIFO が溢れたら数えて、溢れた事実を流れに入れる（黙って欠けない）。
- **内蔵メモリへの記録**: 幅・深さは generic。トリガ（値の一致・立ち上がり等。fprobe の la と同じ考え）、前後の比、
  保存の条件（条件が真のときだけ書く）。
- **信号の選択**: 候補を最大 N 組（generic）つなぎ、JTAG のレジスタで流し続け用・内蔵メモリ用の組を選ぶ。
- **時刻**: 対象のクロックで数える 48 ビット程度のカウンタ。Update-DR（時刻合わせの DR）の瞬間に写し取る。
- **申告**: 版・本数・深さ・組の数・クロック（Hz、任意）・FIFO の深さ。PC はこれを見て動く。信号の名前は回路に入れず、
  作るときに出す名前の表（JSON）を PC が読む（判断。回路を小さく保つ）。
- 目安の大きさ（判断）: 流し続けだけで数百 LUT + FIFO の BRAM 1〜2 個。内蔵メモリへの記録は深さ次第。

## 6. fprobe 側（PYNQ-Z2 だけ）

- **FPGA 観測の口**: 新しいピンの組（TCK・TMS・TDI・TDO・任意で TRST）。PMOD JA（MCU）・JB（ロジアナの専用の入力）
  とは別の空きの端子（Arduino / Raspberry Pi のヘッダ）に置く（判断。端子の場所は作る人が基板の抵抗を確かめて決める。
  docs/boards/pynq-z2.md の PMOD の抵抗の教訓）。
- **obs_jtag_engine**: 既存の jtag_phy と同じビットのタイミング・TCK の速さの設定で、次を回す（ホストの往復なし）:
  - USER の IR を選び、長い DR（例: 4096 ビット）で FIFO を吸い出して、fprobe の記録（深いバッファ / BRAM のリング /
    ストリーム）へ。休まず繰り返す。
  - 時刻合わせ: 時刻合わせの DR の Update-DR の瞬間の fprobe の時刻を記録し、写し取った対象の時刻と組にする。
  - レジスタの読み書き・選択の設定は、PC からの命令で（CSR の新しい窓）。
- **ケイパビリティ**: 新しい機能のビット（例: FEATURE_FPGA_OBS）と、口の数。無い構成（Tang 系）では PC 側の API・MCP の
  道具が「この構成に無い」と答える。
- 速さの目安（判断。対象の基板の JTAG の上限で決まる）: TCK 30 MHz で毎秒 約 3.5 MB、オーバーヘッド 1% 未満。

## 7. 時刻の合わせ方（線なし）

- fprobe が TCK を出すので、Update-DR の瞬間が fprobe の時刻で TCK の 1 周期以内に分かる。
- その瞬間に対象の回路が自分の時刻を写し取る。（fprobe の時刻, 対象の時刻）の組を定期的に（例: 10 ms ごと）取り、
  直線を当てはめる（クロックのずれも補正）。対象のクロックが止まる・変わる区間は、組の連続性から見つけて分ける。
- 目標の精度（判断）: 100 ns 以内（TCK 30 MHz で 1 周期 33 ns + 同期化）。

## 8. MCU と同じ時間軸

- MCU は既存のデバッグの口のまま。MCU の出来事（DAP の転送・サンプラの値・ブレークポイントの停止）はすでに fprobe の
  時刻で記録される。FPGA の記録を §7 で fprobe の時刻に直して、同じ記録・時間軸（既存の recording / timeline）に並べる。
- 線を使わないクロストリガ: 対象の回路のトリガを obs_jtag_engine が見張り（流れの中の印）、既存のクロストリガの源に
  する（MCU を止める・ロジアナを起こす）。遅れは JTAG の 1 スキャン分（数十〜数百 µs）。

## 9. PC 側

- Python の API（`fprobe.fpga_obs`。名前は作る人が決めてよい）: 申告の読み・信号の組の選択・流し続けの開始/停止・
  内蔵メモリの記録と読み・レジスタの読み書き・名前の表の読み込み。
- 既存の記録・時間軸・VCD・解読器に、FPGA の信号を ch として並べる。MCP の道具と API（host/api/fprobe_api.json）に足す。
- 観測の回路を利用者の設計に入れる手伝い: 名前の表とインスタンスのひな形を出す道具（`fprobe_gw obs gen` 等）。

## 10b. 作る人の確認から決めたこと（判断）

- **JTAG の鎖にほかの部品がいる場合**: 既存の jtag_phy と同じく、鎖の上の位置（前後の装置の数・IR の合計）と IR の長さを
  設定で持ち、ほかの部品は BYPASS にする。使う前に目当ての FPGA の IDCODE を照合する。ほかの部品には BYPASS・IDCODE
  以外の命令を出さない。
- **コネクタを利用者の普段の道具（Vivado 等）と取り合う場合**: fprobe が線を手放す（Hi-Z）状態を持つ。利用者がビット
  ストリームを書き直して観測の回路が消えたら、申告が読めなくなったことで見つけて止め、知らせる（読み直しで再開）。
- **流し続けの長さ**: まず fprobe の記録（fprobe_pynq_deep の DDR の深いバッファのリング、32 MB ≒ 3.5 MB/s で約 9 秒。
  止めたら直前を読む）。PC へ無期限に流すのは、PYNQ の中継で数 MB/s を流せることを確かめてからの後の段（O3 以降）。
- **クロックの系統が複数**: 1 つの観測の回路は 1 つのクロック。複数の系統は、複数の観測の回路を 1 つの USER の DR に
  ハブで載せる（O3）。時刻合わせは回路ごとに直線を当てる。O1・O2 は 1 つの回路だけ。
- **レジスタの読み書きのバス**: まず AXI4-Lite のマスタ。Wishbone 等は包みで後から（O4）。

## 11. 利用者の答え（2026-10-20）

- **対象の JTAG の電圧は機器による**: fprobe の端子は 3.3 V のまま。3.3 V の機器は直結、1.8 V・2.5 V 等は外付けの
  レベル変換を挟む前提にし、使い方と速さの目安を文書に書く（判断）。TCK の速さは相手ごとに設定で落とせる。§7 の精度と
  流し続けの量は TCK で決まるので、申告と PC の表示に「今の TCK で流せる量の目安」を出す（判断）。
- **確かめの相手は検討中。Intel の MAX10 も候補**: 観測の回路の包みは Intel（sld_virtual_jtag）を Gowin・Xilinx と並ぶ
  優先にする。手元に MAX10 の基板と Quartus が無いので、O1 の実機の確かめは手元の Gowin（Primer 20K か Tang Nano 4K。
  Primer を使う間は fprobe として使えない）で行い、MAX10 の基板が決まったら Intel の包みを確かめる（判断）。
- **観測の回路のライセンスは Apache-2.0（了承）**: GPL-3.0 の gateware/ とは別の `target_ip/fprobe_obs/` に置き、
  Apache-2.0 の LICENSE を置く。LICENSING.md（公開側）にも足す。

## 12. 作る人に任せること

- DR の形式（命令の DR と流し続けの DR の分け方・長さ）、圧縮の細部、FIFO の深さ。
- PYNQ の「FPGA 観測の口」の端子の場所（空きのヘッダの中で、基板の抵抗・電圧を確かめて）。
- obs_jtag_engine を既存の jtag_phy と共有するか、専用にするか。
- Python の API と MCP の道具の名前。
