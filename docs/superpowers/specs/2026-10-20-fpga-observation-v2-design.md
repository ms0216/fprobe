# FPGA の観測の回路 v2（小さい FPGA に入る形）

2026-10-20。利用者が寝ている間に自律で決めた（朝に報告して見直してもらう）。元の形（v1）は
`2026-10-20-fpga-observation-design.md`。

## なぜ

Shrike-Lite（ForgeFPGA SLG47910、ロジックのブロック 140 個 ≒ 560 LUT）に v1 の観測の回路を入れると、
組 1・FIFO 4 語の最小の構成でも約 620 LUT（ブロック 164 個）になり、観測の回路だけでチップを超えた。
内訳を測ると、観測の量に関係しない固定の部分が大半だった:

- 48（32）ビットの対象の時刻のカウンタ・写し取り・絶対の記録（約 60 LUT・70 FF）
- 32 ビットのレジスタの読み出しと、見出しの語 1〜3 の選択（TCK 側の 32 ビットの選択）
- 64 ビットの命令のシフトレジスタ
- 2 つのクロックをまたぐ非同期 FIFO（グレイ符号の位置の同期）と、TCK をクロックの網に戻す細工（LaC）

利用者の要望（2026-10-20）: 小さい FPGA でも使えること。性能を落とす縮小は勝手に入れず、選べる設定にする。

## 決めたこと

### 1. 時刻は「数えない」。delta を足し合わせ、印の記録で fprobe の時刻と結ぶ

- 対象の時刻のカウンタを持たない。時刻のある記録（値・刻み・印）は前の時刻のある記録からの周期数 delta を持ち、
  PC がそれを足し合わせて対象の時刻にする（桁あふれが無い）。
- 時刻合わせ = 印の記録。fprobe が命令 sync（番号つき）を送ると、対象はその Update-DR を受けた周期に印の記録を書く。
  fprobe は Update-DR の瞬間の自分の時刻をイベント 9（番号つき）にする。PC は番号で両者を組にする。
- 印を書けるのは値の変化の無い周期だけ（値の時刻は常に正確）。待った周期数を印の記録の late に入れる
  （精度は v1 と同じ ±0.5 周期 + 申告した遅れ）。
- 溢れ・開始では delta の鎖が切れる（値の記録の delta = 0 が「鎖の始め」）。鎖の始めから次の印までの値の時刻は、
  印が来てから後ろ向きに決まる（PC は印を待ってから出す）。

### 2. レジスタの読み出しは記録の列で返す

- 読みの命令に、対象は応答の記録（番地・16 ビットの値）を記録の列に書く。TCK 側に 32 ビットの読み出しの
  レジスタも、見出しの語 1〜3 も持たない。見出しは 1 語。
- レジスタは 16 ビット: 0 ID 下位 0x4253、1 ID 上位 0x464F（"FOBS"）、2 VERSION 2、3 GROUPS、4 FIFO_DEPTH、
  5・6 CLOCK_HZ の下位・上位、7 SYNC_DELAY（半周期の単位）、8 SAMPLE_DELAY、9 LOST_BITS、
  14 CONTROL（bit0 = 開始）、15 SELECT（観測する組）。

### 3. 命令は TDI の最後の 16 ビット

op(3:0) | 番地(7:4) | データ(15:8)。op 0 = 何もしない、1 = 書き、2 = 読み、3 = 印（データ = 番号）。

### 4. 1 クロック版（ONE_CLOCK）

- 利用者の JTAG の口を持たない FPGA（obs_soft_tap を使う）では、TCK・TMS・TDI を対象の clk で標本化し、
  TAP も観測の回路も FIFO もすべて clk で動かす（obs_tck_sampler）。非同期 FIFO の同期化も、TCK のクロックの網も要らない。
- 制約: TCK は clk の 1/8 以下（TDO は TCK の立ち下がりから clk の 2〜3 周期後に変わる）。
- BSCANE2 等の利用者の DR（TCK のクロックで動く）には、今までどおり 2 クロック版を使う。RTL は同じ（generic）。

## 記録（32 ビット、31:30 が種類）

| 種類 | 形 | 時刻 |
|---|---|---|
| 0 値 | delta(29:16) value(15:0)。delta 0 = 鎖の始め | あり |
| 1 刻み・印 | 刻み delta(29:16) 0(15:0)（変化なしで 16383 周期）。印 delta(29:16) 1(15) 番号(14:7) late(6:0)（late 127 = 瞬間が分からない） | あり |
| 2 溢れ | lost(15:0)（LOST_BITS の上限で止まる）。鎖が切れる | なし |
| 3 制御 | 種類(29:26): 0 = 組（7:0）、1 = 応答 番地(19:16) 値(15:0) | なし |

開始・溢れの後・組の切り替え: 組 →（溢れ）→ 値（2026-10-23 の R17 で溢れと組の順を入れ替えた: 組を書く周期の変化も失った数に入れるため）。印の後は、変化の無い周期に組と今の値を書き直す
（記録の途中から読み始めても、印から組・時刻・値が分かる）。

## 見出し（TDO の語 0）

count(15:0) | bit16 開始してから溢れた | bit17 clk 側が記録中 | 31:24 = 0xA6（v2 の印。v1 は 0xA5）。続けて count 語の記録。

## fprobe 側

- エンジン（obs_jtag_engine）: 見出し 1 語、命令 16 ビット（最後の語の 31:16）。始めに ID の 2 つのレジスタを読み、
  応答の記録が "FOBS" なら id_ok。応答の記録は read_value（番号・番地・値）にも写す。印の命令は番号を付け、
  その Update-DR の時刻をイベント 9（data = 番号）にする。
- PC（fprobe.fpga_obs）: 命令の組み立て・応答の待ち・delta の足し合わせ・印との組・鎖の始めの後ろ向きの解決。

## 移り

v1 は捨てる（使っているのは本プロジェクトの PYNQ のゲートウェアと Primer の例だけ。同時に v2 にする）。

## 5. 標本型（obs_snap_core。極小の FPGA 向け、2026-10-21 に足した）

v2 の記録型を実際に SLG47910 で配置配線すると、組 1・FIFO 4・LOST_BITS 8 の最小の構成でも約 108〜124 ブロック
（140 個のうち）で、利用者の回路が入らなかった。合成の段階で約 340 LUT（Xilinx の数え方）あり、内訳は「TCK 側の送り出し
と命令」「clk 側の記録の組み立て（6 種類）」「カウンタ（delta・lost・late・位置）」「FIFO」で、作りを保ったままでは
下限に近かった（TDO の送り出しをシフトレジスタから位置の選択に変えても LUT は変わらなかった）。

そこで、規模で選ぶ一番下の段として標本型を置く:

- 回路: obs_tck_sampler + obs_soft_tap（1 クロック版）+ 32 ビットの DR。USER の DR = 0xA7 | 前の Capture-DR からの
  値の変化の回数（255 で止める） | Capture-DR の値。命令・レジスタ・FIFO は無い。SLG47910 で約 21 ブロック。
- fprobe: 見出しの印 0xA7 を見たら ID の照合を省き（id = "SNAP"）、スキャンごとに語 0 を、その Capture-DR を出る
  TCK の立ち上がりの時刻の記録のイベントにする。印のイベントは出さない。
- PC: 値が変わっていれば値、変化の回数から見えた 1 回を引いた数が 1 以上なら先に切れ目（失った数）。open は
  mode = "snapshot" を返し、レジスタの読み書きは「標本型にはレジスタが無い」で断る。
- 失うもの: 周期の精度の時刻（標本の間隔 = スキャンの間隔。TCK 2.5 MHz・1 語で数万回/秒）と、標本の間の変化の中身。

## 6. 実測（2026-10-21、ForgeFPGA SLG47910）

| 回路 | LUT | FF | ブロック（/140） |
|---|---|---|---|
| v1 記録型（組 1・FIFO 4・時刻 32 ビット、clk = TCK） | 516 | 380 | 131 |
| v1 記録型（同、clk は別） | 620 | 398 | 164（入らない） |
| v2 記録型 1 クロック版（組 1・FIFO 4・LOST 16） | 524〜583 | 279〜305 | 124〜135 |
| v2 記録型 1 クロック版（LOST 8） | 474 | 271 | 108 |
| デモ（SPI・計算器）+ 標本型 | 309 | 250 | 63 |
| デモのみ | 189 | 145 | 42 |

v2 は FF を約 3 割減らし、時刻の桁あふれを無くし、1 クロックで動く（TCK のクロックの網が要らない）。LUT は大きくは
減らなかった。記録型を極小の FPGA に入れるには、さらに機能を選べるようにする（応答・印の書き直し・組の切り替えを
generic で外す等。R15 の自動の当てはめの題材）。

## 7. 割り切り（2026-10-21、利用者が了承）

記録型を SLG47910 に入れる試み（応答・書き直し・失った数を外し、値を 8 ビットにした試作）でも 94/140 ブロック（67%）で、
固定の部分（TAP・FIFO・delta・記録の組み立て・TDO の送り出し）が半分以上を使う。よって:
- Shrike 級の極小の FPGA（ブロック 140 個程度）は標本型（約 15%）。周期の精度は持たず、標本の間の変化は回数で示す。
- Tang Nano 4K・9K 以上は記録型（1 割前後）。
- その中間（FIFO を持たず変化を 1 つだけ覚えて読まれるまで待つ形。見込み 3〜4 割）は、要るときに別の設計として起こす。
