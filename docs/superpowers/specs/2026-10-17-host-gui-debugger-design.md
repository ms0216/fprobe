# PC 側 第 4 段: 画面のデバッガ（タブ「デバッガ」）設計

## 1. ゴールと完了条件

第 3 段の画面に「デバッガ」タブを足し、人間がソースの言葉でデバッグする。AI（MCP）が同じ API で行っている
デバッグ（第 1 段）を、人間も画面で見て・交代して続けられる。

| 完了条件 | 検証 |
|---|---|
| 読み込んだ ELF のソースの一覧と本文が見え、止まった行が強調され、その行へ移る | 単体（Python・TS）+ 結合 |
| 行の左端を押してブレークポイントを置く・外す（命令のある行だけ）。一覧からも外せる | 単体（TS）+ 結合 |
| 実行・停止・1 命令・リセット、ELF の読み込み、RAM へ読み込んで止める（試験用のプログラム） | 結合 |
| 止まるたびにレジスタ・呼び出し履歴・登録した変数を読み直す | 単体（TS） |
| 変数のウォッチポイントを置く・外す | 単体（TS） |
| AI が置いたブレークポイント・止めた場所も同じように見える（同じデーモンの状態） | 結合 |
| 実機: sram_demo で、画面からブレークポイント → 実行 → 止まった行・変数・呼び出し履歴 | HIL（画像で確認し報告） |

非目標: 式の評価・構造体の展開（変数は今の `debug.variable.read` の範囲: 1/2/4/8 バイトの整数と 4 バイト要素の配列）、
逆アセンブル、メモリの表示（後で）、Flash への書き込みのボタン（誤操作が重いので画面には置かない。AI・CLI から）。

## 2. 判断

| 判断 | 理由 | 誤っていた場合のコスト |
|---|---|---|
| ソースはデーモンが ELF の行番号の情報（DWARF）から場所を引いて返す。返すのは **読み込んだ ELF が参照するファイルだけ** | 画面が別の PC（`--lan`）でも同じソースが見える。任意のファイルを読ませない | 低 |
| 守る範囲: API の利用者（`--lan` ではトークンを持つ人）は信頼する。ソースを ELF の参照に限るのは誤って別のファイルを読ませないためで、細工した ELF（DWARF に任意の絶対パス）までは防がない。ただし外の共有（UNC）の ELF・ソースは開かない | トークンを持つ人は既に Flash・メモリを書け、任意の場所の ELF を読み込める。UNC は開くだけで認証が外へ出る | 中（守る範囲を広げるなら、ソースを ELF の場所・comp_dir の下に限る） |
| ソースのファイルは名前（basename）で指す（今の `ファイル:行` の書き方と同じ）。同じ名前が 2 つあれば先のもの | 既存の場所の書き方・ブレークポイントと揃える | 低（名前が衝突する大きなプロジェクトで不便。そのとき場所の書き方ごと直す） |
| 実行は `target.resume` + 見張り（第 3 段）で止まったことを知る。見張りの状態に、コアを動かし得る操作を数えた `run` を入れ、同じ場所で止まり直しても読み直せるようにする | `debug.run_until_halt` は作業スレッドを止めるまで占有し、AI の操作が待たされる | 低（止まってから画面に出るまで最大 1 秒） |
| 止まった場所の構造（`function`・`file`・`line`）を `target.status`・止まった結果に足す（`where` の文字列は残す） | 画面が文字列を解釈しない | 低 |
| 画面のデバッガの状態は `src/lib/debugger.ts`（素の TS、store の約束）。部品は表示と操作の受け渡しだけ | 第 3 段と同じ層の分け方 | 低 |

## 3. API に足すもの（版 1 のまま）

| 追加 | 内容 |
|---|---|
| `debug.source.list`（read） | `{"files": [{"name", "path", "exists"}]}`。ELF が無ければ空 |
| `debug.source.read`（read） | 引数 `name`。`{"name", "path", "text", "lines": [命令のある行]}`。ELF の参照に無い名前・無いファイル・2 MB 超は誤り |
| `target.status` / 止まった結果 | `function`・`file`・`line`（分かるときだけ）を足す |
| `debug.elf.load` | 結果に `files`（`debug.source.list` と同じ）を足す |

`Symbols` に `sources()`（名前 → 場所）と `lines_of(name)`（命令のある行）を足す。場所は DWARF 4 は
ディレクトリ番号 0 = `DW_AT_comp_dir`、1 以降 = `include_directories`、DWARF 5 は 0 始まり。

## 4. 画面

```
┌ 作業 | デバッガ | 波形 ──────────────────────────────────────────────────┐
│ ELF [host/firmware/sram_demo/sram_demo.elf      ][読む][RAM へ読み込む]    │
│ [実行][停止][1 命令][リセット]   HALTED  reached_milestone+0 (sram_demo.c:12)│
├──────────┬───────────────────────────────────────┬─────────────────────┤
│ ファイル │  10 │ volatile uint32_t milestone;      │ 変数 [counter ][追加]│
│ sram_demo│ ●12 │ void reached_milestone(void) {  ← │  counter = 256  [×] │
│ stdint.h │  13 │     milestone = counter;          │ 呼び出し履歴        │
│          │     │                                   │  reached_milestone… │
│          │     │                                   │ レジスタ r0..pc     │
│          │     │                                   │ ブレーク/ウォッチ   │
└──────────┴───────────────────────────────────────┴─────────────────────┘
```

- 止まるたび（`target.state` が HALTED で pc が変わった）に、レジスタ・呼び出し履歴・変数を読み直し、止まった
  ファイルを開いてその行へ移す。実行中は値を薄く表示する（古い値であることを示す）。
- ブレークポイントの一覧は `debug.breakpoint.list` を、操作の後と止まったときに読む（AI が置いたものも見える）。
- 操作のボタンは第 3 段と同じく、AI の作業中は確認を出す。自動の読み直しは確認しない。
- ELF の場所はブラウザに覚える。

## 5. 試験

- Python: `Symbols.sources` / `lines_of`（sram_demo.elf）、`debug.source.*`（参照外の名前を拒む、ELF なし）、
  `target.status` の `file`・`line`。
- TS 単体: debugger の状態（止まったら読み直す・同じ pc では読み直さない・止まったファイルを開く・ブレークポイントの
  切り替え・変数の追加と削除・誤り）。
- 結合: 偽の機器（fake_daemon に本物の `Symbols` で sram_demo.elf を読むデバッグの偽物を足す）でソースの一覧・本文・
  ブレークポイントの切り替えと一覧。
- HIL: 実機で画面を開き、画像で確認して報告に残す。既存の HIL（test_debug_hw・test_daemon_hw）が通ること。
