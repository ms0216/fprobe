# 外部ピン入力の限界を測る試験用の方形波（la_testgen）

2026-10-31。内蔵ロジアナ（`fprobe_pynq_cap`、取り込み 300 MHz）が、外部ピンの実信号を、どの速さ・どの幅のパルスまで正しく取れるかを、実測するために作った。
利用者の最優先は、時系列解析の精度（サンプリング周波数・時間分解能）。経緯は `2026-10-30-la-stream-ps-direct-design.md` の 10.17 節。

## 1. なぜ

配線なしの確認（`la_cap.control.selftest`）は、内部信号を入れるので、**入力のバッファ・配線・ピンの限界は測れない**。外部ピンの実信号の限界は、既知の周波数・幅の信号を、
実際のピンから入れて取り込むしかない。手元に高速の信号発生器が無くても測れるように、FPGA 自身が試験の方形波を、別のピンに出し、ジャンパ線 1 本で入力ピンに戻す。

## 2. ゴール・非ゴール

- ゴール: 周期（取り込みのクロックの周期の数）と 1 の幅を指定できる方形波を、ピン 1 本に出す。有効にしたとき以外は、ピンを駆動しない（Hi-Z）。
- ゴール: 位相が固定される問題を、立ち上がり・立ち下がりの 2 通りの出し方で、見落としを減らす。
- 非ゴール: 特定の機器のための機能（CLAUDE.md）。これは機器に依らない、試験用の汎用のパターン出力で、**測定の道具の自己検証**のためのもの。
- 非ゴール: 任意の波形・非同期の信号源（出力と取り込みは同じ MMCM のクロックの整数比。位相が固定される）。信号発生器（案 A）・別の FPGA（案 B）は、より実信号に近い。

## 3. 形

- 回路: `rtl/la/la_testgen.vhd`（cap_clk の領域）。`period`（2〜4095、12 ビット）・`high`（1〜period − 1）・`edge_sel`（0 = 立ち上がりで変える、1 = 立ち下がりで変える = 1.67 ns 遅れる）・`enable`。
  範囲外の値は丸める（出力を固めない: 2 未満は 2、4095 超は 4095、high = 0 は 1、high >= period は period − 1）。ホストは、丸めを黙って受けず、範囲外を断る。
  設定は `cdc_value` で cap_clk の領域に渡し、新しい設定が届くたびにカウンタをやり直す。リセット（`rst`）の間は、enable = 0 と同じ（駆動しない）。
- 作りの経緯: 最初の版は、16 ビットの比較・引き算を 1 周期で行い、cap_clk（300 MHz = 3.33 ns）の setup が −3.4 ns で不合格だった。丸めと引き算をレジスタの数段に分け、出力のカウンタを
  「ゼロまで数える下りカウンタ」（1 の区間と 0 の区間で読み込み直す）にして解消した。周期は 12 ビット（1 MHz = 300 で足りる）。設定が出力に届くまで 6 周期かかる。
- レジスタ: `la_cap.testgen`（enable・edge）・`testgen_period`・`testgen_high`。`fprobe_core` の `la_cap_info`（CAP_RATIO > 1）の中に置く。
- ピン: PYNQ-Z2 の RPi ヘッダ 32 番（GPIO12、ピン B20）、DRIVE 8・**SLEW FAST**（既定の SLOW では、150 MHz の方形波が振幅を保てない）。`Pin` に `slew` を足した。
  トップで `testgen_oe` のとき以外は `'Z'`。入力側は PMOD JB の 1 番（ロジアナの ch 10 = `in0`）。配線は `docs/hardware-wiring-request.md`（linux-awareness-trial 側）3.1 節。
- ホスト: `LogicAnalyzer.testgen(period, high, edge)`（出力の周波数 Hz を返す）・`testgen_off()`。取り込みのクロックが sys の整数倍の構成だけ（それ以外は `RuntimeError`）。

## 4. 確かめ方

- シミュレーション（cocotb）: 周期・high の波形、範囲外の丸め、enable = 0 で駆動しない、edge = 1 が半周期遅れる、リセットで駆動をやめて解除後に戻る。ホスト（偽のデバイス）: 順序（周期・high → enable）・範囲外の拒否・対応しない構成の拒否。
- ビルド（Vivado 2025.2、`fprobe_pynq_cap`）: `Default` の配置は −0.007 ns（既存の取り込み部の 1 本。追加部品ではない）で不合格、`Explore` が合格（WNS +0.006 ns、cap_clk Fmax 300.571 MHz、sys_clk Fmax 100.070 MHz）。
  **リセットを足した版（`8169efd2`）のタイミングは、再ビルドでの確認が要る。**
- 実機（PYNQ-Z2、ジャンパ線 1 本のループバック。GND の 2 本目は未確認）:
  - 方形波（50 % 近く）: 周期 20 以上（15 MHz 以下）は、edge = 1 で、1 と 0 の連続の長さが**設定どおり**。edge = 0 は 1 サンプル（3.3 ns）ずれる（1 の区間 +1、0 の区間 −1。合計は周期と一致 = 欠けも重複もない）。
    周期 6〜12（25〜50 MHz）は、どちらの edge も ±1 サンプルずれる。周期 2〜4 と 5（high = 3）は、波が見えないものがある。
  - 狭いパルス（周期 40）: 1 の幅 1 サンプル（3.3 ns）は一度も見えない（204 個中 0）。2 サンプル（6.7 ns）は長さが 1 か 2。3 サンプル（10 ns）は edge 0 で一致、edge 1 で 2 か 3。
    **4 サンプル（13.3 ns）以上は、edge = 1 で、すべて見えて幅が一致**（4・5・6・8）。0 のパルスは、どの幅も 1 サンプル短く見え、1〜2 サンプルは見えない。
  - **再ビルド版（`8169efd2`、設計 ID `835b0b663dbba1b3`、2026-10-31）で再測定**: 周期 30 以上の方形波は、edge の別なく 1 の区間が +1、0 の区間が −1 サンプル（周期 300 で 0 = 149、1 = 151）。合計は周期と一致（欠けも重複もない）。周期 20 の edge = 1 だけ設定どおり。
    旧版と違う理由は未確認（推測: 立ち上がりと立ち下がりの入力遅延の差が、配置の違いでサンプル境界の反対側に動いた）。`test_slow_square_waves_are_reproduced_exactly` は周期 300・60・30 で失敗する（9 件中 6 件通過）。
  - 実機の試験: `gateware/tests/hil/test_pynq_cap_testgen_hw.py`（9 件通過。ジャンパ線がつながっていなければ skip）。

## 5. 読み取りと限界

- **このループバック全体（出力の駆動・ジャンパ線・入力のバッファ）の限界**が、約 13 ns のパルス幅（約 40 MHz の 50 % の方形波）。立ち上がりが早く、立ち下がりが遅く見える一定の差がある。
- **取り込み回路だけの限界は、ここからは言えない**（出力の駆動・線の長さ・入力のバッファを分けていない）。分けるには、GND の 2 本目（RPi ヘッダ 34 番 ↔ JB の 5 番）を並べて短くした再測定、より速くきれいな信号源（信号発生器・別の FPGA）が要る。
- 未着手: 垂れ流し用の回路（`fprobe_pynq_deep`、取り込み = sys）にも、同じ方形波を足す（ケイパビリティ `la_testgen`、コアの generic、ホストの判定をケイパビリティに）。垂れ流しの画面で矩形波を見せ、
  チャンネル詰めの中身を実機で確認するため。`pack` は ch 0〜7 だけを流すので、そのためには、方形波を ch 0〜7 に出す経路が要る（JA のピンは SWD・JTAG の線と兼用）。設計が要る。
  - **再ビルド版 2（`la_testgen` を CSR ブロック `la_testgen` 0x0CC0 に移した版、設計 ID `661422a30389533d`、`C:\fw51`、cap_clk Fmax 301.1 MHz・sys_clk Fmax 104.9 MHz、TNS 0、2026-11-01）**:
    周期 20〜300 の方形波は、欠けも重複も無い（隣り合う 1 と 0 の合計 = 周期）が、1 の区間が +1、0 の区間が −1 サンプル（edge = 1 でも。周期 300 で 0 = 149、1 = 151）。狭いパルスは幅 4・5 が一致、6 は 6 か 7、8 は 9。
    ずれ方は**ビルドの配置ごとに変わる**（`fw49c` と `fw51` で違う）ので、実機の試験の期待は「厳密一致」から「欠けなし（合計 = 周期）・幅の差が ±1 サンプル以内」に直した（許容は試験が明示。`TOLERANCE`）。9 件通過。


## 再測定（2026-11-01、GND の 2 本目あり）

RPi ヘッダ 34 番（GND）↔ PMOD JB の 5 番（GND）を足し、方形波の線（RPi ヘッダ 32 番 → JB の 1 番）と並べた状態で、`fprobe_pynq_cap`（`C:w51`、ID 661422a30389533d、300 MS/s）の `test_pynq_cap_testgen_hw.py` を流した（9 件通過）。

| パルス幅 | 見えた回数 | 記録された長さ |
|---|---|---|
| 1 サンプル（3.3 ns） | 0 / 205 | — |
| 2 サンプル（6.7 ns） | 205 / 205 | 1 サンプル（縮む） |
| 3 サンプル（10.0 ns） | 205 / 205 | 3 サンプル |
| 4 サンプル（13.3 ns） | 205 / 205 | 4 サンプル |

- GND 1 本のときは約 13 ns が見える限界だった。GND の 2 本目で、10 ns のパルスの幅を正しく記録でき、6.7 ns も欠けずに捉える（幅は縮む）ようになった。
- 線の帰り道（GND）がこのループバックの限界を決めていた部分がある、という事実。取り込み回路そのものの限界は、まだ分離していない（より速くきれいな信号源が要る）。
