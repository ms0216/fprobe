## 0. 要約

- 端子の ISERDESE2 が sys（100 MHz）の 1 周期に渡す 8 サンプル（800 MS/s、`fprobe_pynq_fast` と同じ取り込み）を、深いバッファの
  垂れ流しに **N = 8 並列で**符号にする新しい構成 **`fprobe_pynq_deep_fast`**。内蔵バッファ・トリガ取り込みは持たない（垂れ流しだけ）。
- **RLE（変化点）を N 並列に**: 1 周期の 8 サンプルの中の変化の位置ごとにレコード（今と同じ 32 ビット = 数 − 1 | 値）を閉じ、
  1 周期に最大 8 レコード。数の単位は細かいサンプル（1.25 ns）。費用は変化の数に比例（1 変化 4 バイト）: 50 MB/s で毎秒 1250 万回。
- **RAW の詰めを N 並列に**: 語の中のサンプルを 2^step 個ごとに選び（800・400・200 MS/s と、100 MS/s ÷ (rate + 1)）、ch を
  16・8・4・2・**1** 本に詰め、詰める最初の ch（`first`）を選べる。1 拍の形は今の RAW・`la_pack` と同じ（ホストの解読は同じ）。
- **始める前に量が決まる RAW は、デバイスが申告する持続できると測った速さ（50 MB/s）を超える組を始める前に断る**（使う側が上限を明示すれば
  そちら）。RLE は断らない（量は信号次第）。溢れは今と同じく事実（overrun）として返し、届いた分は欠けの無い先頭の部分。
  使う側が明示して選べば（`gaps`。段 B、§12）、溢れても止めず、回路が捨てた区間（欠け）を位置と長さの事実として返して続ける。
- **リング（DDR）と帯域の使用量を事実として API で返す**（回路に数えを足した: 書いた総数・未読・未読の最大。ホストが毎秒の量を計算）。
- 時刻: 流れの細かいサンプル s の値に変わったピンは、辺 **n = start_time × 8 + s × d − latency**（d = サンプルの間隔、latency = 8 + 5 = 13）
  の後に変わった。起点 start_time（最初に符号にした語の時刻）を回路が記録する（これまでの垂れ流しはホストの往復で推定していた）。

## 1. 要求と、今の限界

- 要求（主担当、2026-11-01）: 垂れ流し（深いバッファ・長時間・間引きなし）でも 800 MS/s の細かさを保つ。帯域の壁は PC への約 50 MB/s。
  RAW でも、帯域に収まる ch 数とレートの組は流せる。収まらない組は断る（黙って捨てない）。溢れたら事実として記録する今の仕組みを保つ。
- 補足（利用者との確認、主担当経由）: 「断る」のは RAW だけ（量が始める前に決まる）。RLE は変化の頻度で量が決まるので断らず、DDR のリングで
  一時的な変化の多さを吸収し、溢れたら事実を記録する。最悪（毎サンプルの変化）の RLE が RAW を超えることを数値で書く。帯域の見込みは
  信号の変化の頻度ごとの表にする。
- 追加の要求（Saleae Logic 2 の調べから）: 垂れ流しの間のリングの使用量・帯域の使用量（毎秒の符号のバイト数・送ったバイト数）を、API で
  事実として返す（ホストで計算し、画面は描くだけ）。止めるかの判断は使う側。Saleae との違いを書く（§6.3）。
- ［事実］今の深いバッファ（`fprobe_pynq_deep`）の符号器 `la_encoder` は sys の 1 周期に 1 サンプル（100 MS/s で頭打ち）。`fprobe_pynq_fast`
  の 800 MS/s は内蔵バッファ（164 µs）だけ（`la-resolution` §11・§12）。

## 2. N 並列の RLE（`rtl/la/la_lane_rle.vhd`）

### 2.1 符号（主担当の判断: レコードの形は変えない）

- レコード = 32 ビット: 上位 16 = 繰り返しの数 − 1、下位 16 = 値（今の `la_encoder` の RLE と同じ。1 拍 = 4 レコード、下位から時間順）。
  数の単位だけが細かいサンプル（1 / la_sample_hz = 1.25 ns）。**ホストの解読（`fprobe.la.decode_beats(rle=True)`）は変えない**。
- 理由: 位置を「語の中の変化のビット列（8 ビット）」で符号にする形（1 語 = 変化の印 8 ビット + 変化した値）も考えたが、変化の少ない区間で
  毎語の印が要り（毎秒 1 億語 × 1 バイト = 100 MB/s）、垂れ流しの目的（変化の少ない信号を長く）に反する。レコードの形なら変化の無い区間は
  65536 サンプル（81.9 µs）に 1 レコード（約 49 KB/s）で、形も解読も今と同じ。

### 2.2 1 周期の処理（無損失の約束）

- 語のレーン k（k = 0 が最も古い）の変化 c(k) = 値(k) ≠ 値(k − 1)（レーン 0 は前の語の最も新しいレーンと比べる）。
- 作りかけの続きの長さ L（前の語から続く同じ値のサンプルの数。0 = 続きが無い）。c(k) = 1 の位置ごとに、その前の続きを閉じる:
  最初の変化 k₀ は長さ L + k₀（前の語から続いた分を足す）、次からは隣の変化との差。値はその続きの値（レーン k − 1、k = 0 なら前の語の値）。
  続きが無い（L = 0）ときはレーン 0 では閉じない（長さ 0 のレコードを作らない）。
- 変化の無い語は L に 8 を足す。**L が 65536 − 8 を超えたら語の終わりで閉じる**（L ≤ 65528 を保つので、最初の変化の長さ L + k₀ ≤ 65535
  も、変化の無い語の L + 8 ≤ 65536 も、数の欄（16 ビット = 65536 まで）に必ず収まる）。閉じた次の語は新しいレコードから（同じ値でも）。
- 1 周期に閉じるレコードは最大 8 個（全レーンで変化）。語の終わりで閉じるのは変化の無い語だけなので、合わせても 8 個を超えない。
- 開始（run の 0→1）の次の語のレーン 0 から始め、止める（1→0）と作りかけのレコードと 4 個に満たない溜めは出さない（今の `la_encoder` と同じ）。

### 2.3 詰めと溜め・溢れ

- パイプライン 4 段: 隣のサンプルとの比較 → 閉じるレコード → 時間の順に詰める（8 個の中の有効なものを前へ）→ 溜め（16 レコード）と拍。
- 溜めから 4 個たまるごとに 1 拍（1 周期に 1 拍まで = 4 レコード/周期 = 毎秒 4 億レコード）を出す。受け手（深いバッファの非同期 FIFO）が
  受けられない間は溜めに残す。
- **溜めに入りきらないレコードが出たら overflow を 1 回立て、そのレコードと以後のレコードを入れない**（start まで）。溢れる前に溜めに入った
  レコードは出し切る。**届いた拍は欠けの無い先頭の部分**（試験 §8 で確かめる）。深いバッファの `overrun` になる（`la_lane_encoder`）。
- 吸収の段: 溜め 16 レコード（約 2 周期分の全変化）→ 非同期 FIFO 512 拍（2048 レコード）→ DDR の書き込み → **DDR のリング（ロジアナの分
  30 MiB = 31,457,280 バイト = 1,966,080 拍、32 MiB の 15/16。10 進で約 31.5 MB）**（2026-11-02 に「約 30 MB」から直した。`la_deep_buffer.vhd` の
  EV_SIZE = 全体の 1/16・LA_SIZE = 残り、全体は `designs.py` の 32 MiB。performance-limits §7.1）→ PS の中継 → PC。リングを超えた未読は今と同じ「リングに迫ったら書き込みを止めて overrun」（§6.2）。使う側が `gaps` を明示した流れでは、
  リングに迫ったら書き込みは止めず、符号器の出口で拍まるごと捨てて欠けの区間を記録して続ける（段 B、§12。符号器の溜めの溢れは gaps でも止まる、§12.4）。

### 2.4 最悪の場合の大きさ（RLE が RAW を超える）

| 入力 | RLE の量 | RAW 16 ch（800 MS/s） | RAW 1 ch（800 MS/s） |
|---|---|---|---|
| 毎サンプルの変化（400 MHz の方形波、または 16 ch のどれかが毎サンプル変わる） | 8 億レコード/s × 4 B = **3.2 GB/s** | 1.6 GB/s | 100 MB/s |
| 2 サンプルに 1 回（200 MHz の方形波） | 1.6 GB/s | 同 | 同 |

- 最悪の RLE は **RAW 16 ch の 2 倍、RAW 1 ch の 32 倍**。回路の出口（1 拍/周期 = 1.6 GB/s = 4 レコード/周期）も超えるので、毎サンプルの
  変化が溜め（16）を超えて続くと、数周期で overflow になる（試験 `a_change_at_every_sample_makes_eight_records_a_cycle_and_overflows`）。
- RLE が RAW より小さいのは、変化の頻度 f（毎秒の値の変化の数）が RAW の量 / 4 B より小さいとき。16 ch の RAW（1.6 GB/s）より小さいのは
  f < 4 億回/s、1 ch の RAW（100 MB/s）より小さいのは f < 2500 万回/s。

### 2.5 帯域の見込み（信号の変化の頻度ごと。計算 = ［推測］、実機の長時間は §9）

RLE の量 = 4 B ×（16 ch の値が変わるサンプルの瞬間の数/s + 変化の無い区間の分割 約 1.2 万/s）。同じサンプルで複数の ch が変われば 1 回。
持続できるか = PC への約 50 MB/s（申告）以下か。超える山は DDR のリング（30 MiB = 約 31.5 MB）が「31.5 MB ÷（量 − 50 MB/s）」の間だけ吸収する。
（2026-11-02 の追記: ゼロコピーの中継（`bandwidth-observation` §1.7.9。モジュールを手で読み込んだときだけ）では RAW 16 ch の 66.7 MB/s が 60 秒溢れず、
100 MB/s は溢れた。申告 `LA_STREAM_BYTES_PER_S` は 50 MB/s のまま（`designs.py`）。下の表の「50 MB/s の壁」は申告の値で、ゼロコピーの道の
実際の上限は 66.7 と 100 MB/s の間のどこか（測った段はこの 2 つだけ）。）
PL の中の上限: 符号器の出口 1.6 GB/s（4 億レコード/s）、DDR の書き込み［推測］約 530 MB/s（`la-resolution` §1.4。HP0 の書き手の見積り）。

| 信号（16 ch のうち動くもの） | 変化の瞬間/s | RLE の量 | 50 MB/s の壁に対して |
|---|---|---|---|
| 変化なし | 0（分割 1.2 万） | 0.05 MB/s | 持続 |
| UART 115200 baud（連続送信） | ≤ 11.5 万 | ≤ 0.46 MB/s | 持続 |
| UART 1 Mbaud | ≤ 100 万 | ≤ 4 MB/s | 持続 |
| I2C 400 kHz（SCL + SDA） | 約 120 万 | 約 4.8 MB/s | 持続 |
| SWD 4 MHz（SWCLK 800 万 + SWDIO ≤ 400 万、転送の間） | ≤ 1200 万 | ≤ 48 MB/s | 転送が続く間はぎりぎり（転送の合間で平均は下がる） |
| 方形波 1.33 MHz（la_testgen 周期 300 = §9 の試験） | 267 万 | 10.7 MB/s | 持続 |
| 方形波 2.67 MHz（周期 150） | 533 万 | 21.3 MB/s | 持続 |
| 連続のクロック 10 MHz | 2000 万 | 80 MB/s | 超える: リングで約 1 秒（31.5 MB ÷ 30 MB/s） |
| SPI 10 MHz（SCK + MOSI + MISO、転送の間） | ≤ 4000 万 | ≤ 160 MB/s | 転送の山（例 1 ms = 160 KB）はリングで吸収、続けば超える |
| 連続のクロック 50 MHz | 1 億 | 400 MB/s | 超える: リングで約 90 ms |
| 連続のクロック 200 MHz | 4 億 | 1.6 GB/s | DDR の書き込みを超える: 非同期 FIFO（8 KB）で数 µs |
| 毎サンプルの変化（400 MHz） | 8 億 | 3.2 GB/s | 符号器の出口も超える: 数周期で溢れ |

RAW の量（始める前に決まる。ch / 8 × レート）と、申告の 50 MB/s に収まる組（ホストはこれを超える組を断る）:

| ch（first から詰める） | 800 MS/s（1.25 ns） | 400 MS/s | 200 MS/s | 100 MS/s | 50 MB/s に収まる最高のレート |
|---|---|---|---|---|---|
| 1 | 100 MB/s | **50** | 25 | 12.5 | 400 MS/s（2.5 ns） |
| 2 | 200 | 100 | **50** | 25 | 200 MS/s（5 ns） |
| 4 | 400 | 200 | 100 | **50** | 100 MS/s（10 ns） |
| 8 | 800 | 400 | 200 | 100 | 50 MS/s（d = 16） |
| 16 | 1600 | 800 | 400 | 200 | 25 MS/s（d = 32） |

- 1.25 ns の細かさのまま長く流せるのは **RLE**（変化の少ない信号）。RAW の 800 MS/s は 1 ch でも 100 MB/s で、今の壁（50 MB/s）を超える
  （初版は「ゼロコピーの中継で約 100 MB/s の見込み = `bandwidth-observation` 1.7 が入れば、1 ch・800 MS/s が収まる［推測］」と書いた。
  2026-11-02 の実際の流れの実測（`bandwidth-observation` §1.7.9、`fprobe_pynq_deep` の RAW 16 ch）では、ゼロコピーの道で 66.7 MB/s は 60 秒溢れず、
  100 MB/s は 2.4〜4.5 秒で溢れた。同じ 100 MB/s の 1 ch・800 MS/s も持続しない見込み［推測: 同じ中継・TCP の道で、量が同じため。
  `fprobe_pynq_deep_fast` では測っていない］。持続しない組を欠けを記録して流すのは段 B（§12、`gaps`））。

## 3. N 並列のチャンネル詰め（`rtl/la/la_lane_raw.vhd`）

- サンプルの選び（主担当の判断: 回路が作れる間隔だけ。丸めずに断る）: 語の中のレーン 0・2^step・2 × 2^step … の 8 / 2^step 個
  （細かいサンプルの 2^step 個ごと = 800・400・200・100 MS/s）。step = 3（語に 1 サンプル）のときは、さらに la.rate + 1 語ごとに 1 語
  （100 MS/s ÷ (rate + 1)）。サンプルの間隔 d（細かいサンプルの数）= 1・2・4 か 8 の倍数（8 × 65536 まで）。それ以外の間隔（3・6 等）は
  ホストが ValueError で断る（`lane_divisor`）。**間引きではない**: 使う側が明示したサンプルレートで、そのレートのサンプルは 1 つも欠けない
  （今の `rate` と同じ扱い。既定は 800 MS/s）。
- ch の選び: 1 サンプル c = 16 / 2^pack ビット（pack 0〜4 = 16・8・4・2・1 ch）、詰める ch は **first〜first + c − 1**（主担当の判断:
  `first` を足した。理由: 細かく取る専用の入力は PMOD JB = ch 10〜15 で、ch 0 から詰める今の `la_pack` の形では RAW の 1・2・4 ch に
  入らない。JA の ch 0〜7 は SWD・JTAG の線と兼用）。ホストは first + c ≤ 16 でない指定を断る。
- 拍: 1 語の M × c ビット（M = 8 / 2^step、2 の累乗）を、**時間の古いものが下位**になるように 128 ビットに詰める（新しいビットを上から入れて
  右へ送る）。128 / (M × c) 語で 1 拍。c = 16 なら 1 拍 = 8 サンプル（今の RAW と同じ）、c < 16 なら `la_pack` の語を 8 つ並べたものと
  同じビットの並び。**ホストの解読（`_expand_words`）は同じ**（pack = 4 = 1 語 16 サンプルは同じ式で動く）。
- パイプライン 3 段（ch の寄せ → 選び → 詰め）。拍は止められない（保持レジスタが空かないうちに次の拍が出たら overrun、以後は作らない）。

## 4. 構成（`fprobe_pynq_deep_fast`）

| 項目 | 値 | 根拠・判断 |
|---|---|---|
| 取り込み | PMOD JA の 8 本・JB の 6 本（14 本）を ISERDESE2（CLK = cap_clk 400 MHz の両方の辺、CLKDIV = sys）。N = 8、800 MS/s | `fprobe_pynq_fast` と同じトップ・ラッパー（`la-resolution` §11） |
| 深いバッファ | PS の DDR の 32 MiB（ロジアナ 30 MiB = 1,966,080 拍 + イベント 2 MiB）、HP0、PS 直読み・TCP | `fprobe_pynq_deep` と同じ |
| 内蔵バッファ | 無い（la_depth = 0） | 主担当の判断: 1 つの構成に内蔵と深いバッファを両方持たない今の約束（`designs.py`）を保つ。`la_sample_hz` は垂れ流しの細かさ（1 つの意味） |
| トリガ取り込み | 無い（深いバッファのトリガ取り込みはホストが断る） | 主担当の判断: 目的は垂れ流し。トリガの位置（レーン）と RLE のトリガのレコードの境は、後の段で作る（§11） |
| グリッチフィルタ・パルス幅 | 無い（la_filter・la_pulse = 偽） | `fprobe_pynq_fast` と同じ |
| 方形波 | la_testgen（400 MHz で刻む） | 実機の試験 §9 |

- RTL: `fprobe_core` の `USE_DEEP_LANES`（LA_LANES > 1・外部メモリあり・内蔵なし）で、`la_deep_buffer` の generic `LANES = 8`・
  `IN_AGE = iserdes_newest_age(8) = 5`。`la_deep_buffer` は LANES > 1 のとき `la_front`・`la_pack`・`la_encoder` の代わりに
  `la_lane_encoder`（`la_lane_raw` + `la_lane_rle` + 保持・溢れ・起点の時刻）を使う。メモリ・リング・PS 直読み・見出し・中継・TCP は変えない。
- 内部の ch（SWDIO を駆動中・DAP の処理中）は sys の信号を全レーンに並べる（`fprobe_pynq_fast` と同じ。時刻の分解能は sys の周期）。

## 5. ケイパビリティと CSR

- 既存: `la_sample_hz` = 800 MHz、`LA_FINE` = 0xFCFF（ホストは `la_sample_hz / sys_clock_hz` = 8 を語のサンプルの数として使い、
  `la_deep.info.lanes` と突き合わせる。合わなければ流さない）、`la_pack`・`la_stream_ps`・`la_stream_events`、`la_testgen`。
- 新しい TLV 24 **`LA_STREAM_BYTES_PER_S`**（u32、B/s）: この構成で深いバッファの垂れ流しを持続できると**測った**速さ。PYNQ の深いバッファの
  構成（`fprobe_pynq_deep`・`fprobe_pynq_deep_fast`）は 50 000 000（RAW 16 ch・25 MS/s の 60 秒を 11 回中 11 回、8 ch・50 MS/s と
  4 ch・100 MS/s の 60 秒を各 2 回欠けなし。`ps-direct` §10.14・§10.16）。
  - 主担当の判断（原則との整合）: これは経験則の閾値ではなく、測った値（方法と条件を `designs.py` の注とこの文書に書いた）をデバイスが申告する
    事実。ホストは RAW の量（ch / 8 × レート。推定ではなく計算）がこれを超える組を始める前に断る。PC・回線・中継の版で変わる値なので、
    使う側が `max_bytes_per_s` で明示すればそちらを使う（例: ゼロコピーの中継で上がった後）。申告の無い構成（Primer 等）は断らない。
- 新しい FEATURES bit15 **`LA_STREAM_USAGE`**: la_deep の数え（下の 0x34〜0x48）がある（深いバッファのある構成は全部。古い回路には無い）。
- CSR `la_deep`（ブロックを 0x40 → 0x80 に広げた）:
  - `control.pack` を 3 ビットに（4 = 1 ch。LANES > 1 の構成だけ）、`control.step`（ビット 8〜9）、`control.first`（ビット 12〜15）。
  - `la_written`（0x34）書いた拍の総数、`ring_unread`（0x38）書いた − 読んだ、`ring_peak`（0x3C）未読の最大、
    `start_time_lo/hi`（0x40・0x44）最初に符号にした語の時刻、`info`（0x48: lanes・latency・start_valid）。
- LA_CH_TIMING: 細かい ch（JA・JB）の深いバッファの欄 = 0（軸そのもの）、内蔵の欄 = None（無い）。内部の ch は None（確かめていない）。

## 6. 溢れ・リングと帯域の使用量・Saleae との違い

### 6.1 使用量の事実（API）

- 回路（mem で数え、16 周期ごとに sys へ）: 書いた総数（`la_written`）、未読（書いた − 読んだ。PS が読む流れは PS が返した位置との差）、
  流れの開始からの未読の最大（`ring_peak`。ホストが読む間の山も残る）。
- ホスト `LaStream.usage()`（呼ぶたびに `usage_history` に足す）: `ring_beats`・`ring_unread_beats`・`ring_peak_beats`、
  `encoded_bytes`（= 書いた拍 × 16、32 ビットの折り返しを伸ばす）、`received_bytes`、前の読みからの `encoded_bytes_per_s`・
  `received_bytes_per_s`、`overrun`、`unknown`（古い回路で取れない欄の名前。0 で埋めない）。
- API: `la_stream`（VCD）の結果に `usage`（`usage_interval_s` ごとと終わり）、`recording_la_stream` の status に `usage`（読むたび）。
  画面はこの値を描くだけ（割合や「危ない」の色の基準は持たない。原則）。

### 6.2 溢れたとき（今の仕組みを N 並列でも保つ）

| どこで | 何が起きる | 記録される事実 |
|---|---|---|
| RLE の溜め（16 レコード）・RAW の保持レジスタ | 入りきらない分から先を作らない（届いた分は先頭から欠けなし） | `status.overrun` |
| 非同期 FIFO（512 拍）が満杯 | 同上（符号器の拍が出られない） | 同 |
| DDR のリングの未読が「リング − 256 拍」に迫る | 書き込みを止める（未読を上書きしない） | 同（`ring_peak` に山） |
| （`gaps` の流れ。段 B、§12）リングの未読が「リング − GAP_HOLD」を超える・非同期 FIFO が受けない | 書き込みは止めず、符号器の出口で拍まるごと捨て、空いたら再開する | 欠けの記録（イベント 19: 位置 b・サンプル数 q）、`status.gap_open`・`gaps`・`gap_last_beat`。リング − 256 の安全の網・符号器の溜めの溢れは上の行と同じく overrun |

- ホストの `LaStream.chunks` は overrun を見たら止める（デバイスの書き込みが既に止まっているため）。それまでの分は正しい。
  `gaps` の流れでは、欠けで分けたチャンク（`StreamChunk.gap`）を返して続ける（§12.1・§12.5）。

### 6.3 Saleae Logic 2 との違い（設計の理由）

| | Saleae Logic 2（調べた範囲、主担当経由） | fprobe |
|---|---|---|
| 送り方 | 変化だけを送る | RLE（変化だけ）と RAW（ch を詰めた全サンプル）を使う側が選ぶ |
| レートの上限 | チャンネル数でレートの上限を決め打ち（表） | RAW は「ch / 8 × レート」を計算し、デバイスが申告する測った速さ（または使う側が明示した上限）と比べて、超える組を**始める前に**断る。RLE は断らない |
| 溜まりの扱い | PC 側の溜まりが 90 % を超えたら取り込みを止める | **閾値で止めない**。リング・帯域の使用量を事実として返し、止めるかは使う側が決める。物理的に書けなくなったとき（リングが満杯）だけ書き込みが止まり、その事実（overrun・山）を返す。使う側が `gaps` を明示すれば、止めずに欠けの区間（位置と長さ）を記録して続ける（段 B、§12） |

- 理由: (1) 間引き禁止（利用者の方針）: 量を減らすために黙ってサンプルを落とさない。RAW の組を断るのは「黙って捨てる」代わりに「始めない」こと。
  (2) ヒューリスティック禁止（CLAUDE.md の絶対の原則）: 「90 % で止める」のような経験則の閾値は、別の使い方（短い山を許す・最後まで取りたい）
  で誤った結論に導く。判断は使う側（人・AI）がする。(3) 決め打ちの表はボード・PC・中継で変わる事実を隠す: fprobe は測った値をデバイスが申告し、
  使う側が上書きできる。
- ［事実］既定（`gaps` = false）の fprobe は、リングが満杯になったら**書き込みを止めて流れが終わる**。約束は「届いた分は欠けの無い先頭の
  部分 + overrun の事実」。使う側が `gaps` = true を明示したときだけ、「止めずに、欠けの区間（位置と長さ）を記録して続ける」形（段 B。
  2026-11-02 に実装、§12）。

## 7. 時刻の式（`la_lane_encoder`）

- 入力の語（clk の立ち上がり w の後に lane_data に出た語）のレーン k は、細かいサンプルの辺 8w − (7 − k) − IN_AGE で取ったサンプル
  （`la_lane_capture` と同じ約束。IN_AGE = 5 は UNISIM の ISERDESE2 の記録から。`la-resolution` §8）。
- start_time = 最初に符号にした語の時刻（その語が lane_data に出ていた周期の time）。流れの細かいサンプルの番号 s（最初の語のレーン 0 = 0）
  の値に変わったピンは、**辺 n = start_time × 8 + s × d − latency の後に変わり、辺 n + 1 で取られた**（latency = 8 + IN_AGE = 13。
  d > 1 なら、変化は辺 n − d + 1〜n の後のどこか）。ホスト `LaStream.sample_time(s)` が返す（edge・edge_lo・edge_hi・edge_hz）。
- ［事実］ISERDESE2 の模型を通した端から端の試験（§8）で、RAW の全サンプル・RLE の全サンプルについて、この式の辺のピンの値と一致した。
- 他の情報源（イベント・DAP）との比較は sys の刻み（10 ns）の不確かさが残る（`time-accuracy`）。記録（`recording_la_stream`）の時刻は
  タイムベースの刻みの整数なので、**刻み（10 ns）の整数倍でないサンプルの間隔では始める前に断る**（黙って丸めない）。細かい時刻のまま残すのは
  VCD への垂れ流し（`la_stream`）。

### 12.1 仕組み

| どこで | 何をする |
|---|---|
| mem（`la_deep_buffer`） | `control.gaps` の流れでは、ロジアナのリングの未読が `LA_SIZE − GAP_HOLD` を超えたら **hold** を立て（書き込みは止めない）、`LA_SIZE − GAP_HOLD − GAP_ROOM` 以下に減ったら下ろす。hold は sync_bit で sys へ。GAP_HOLD = min(1024, リング / 4) 拍、GAP_ROOM = min(4096, リング / 4) 拍（PYNQ のリング 1 966 080 拍では 1024・4096） |
| sys（新しい部品 `la_stream_gap`、符号器と非同期 FIFO の間） | 符号器を止めない（`in_ready = 1`）。拍を出せない周期（hold = 1、または FIFO が受けない）の拍は**拍まるごと**捨て、捨てたサンプルの数を数える（RAW: 1 拍 = 2^(3 + pack) サンプル、RLE: 拍の 4 レコードの長さ（数 + 1）の和）。hold = 0・FIFO が半分未満（`async_fifo` に足した `in_below_half`）・受け口が空いた周期に、**欠けの記録**（イベント、種類 19 = `EVENT_KIND_LA_GAP`）を FIFO に入れ、次の拍から出すのを再開する |
| 欠けの記録（128 ビット） | [47:0] 拍を捨て始めた周期の time、[79:48] **b** = 欠けの前に出したロジアナの拍の数（流れの開始から。32 ビットで折り返す。ストリームの見出しのロジアナの通し番号と同じ数え）、[119:80] **q** = 捨てたサンプルの数（流れのサンプルの単位）、[127:120] 19。q が 2^39 に達したら同じ b のまま件を分ける |
| CSR | `control.gaps`（bit 16）、`status.gap_open`（bit 5: いま捨てている。止めた後も次の開始まで残る）、`gap_last_beat`（0x4C）、`gaps`（0x50: この流れで出した記録の件数）。FEATURES bit 17 `LA_STREAM_GAPS`（`Capabilities.la_stream_gaps`。PYNQ の `fprobe_pynq_deep`・`fprobe_pynq_deep_fast` だけ。回路は `la_deep_buffer` の generic `STREAM_GAPS`、`fprobe_core` の `LA_STREAM_GAPS`） |
| ホスト（`fprobe.la.GapPlacer`・`LaStream`） | 欠けの記録はイベントに入れず、届いた拍の列の b の位置に「値の無い区間」として置く（埋めない・補わない）。チャンクは欠けで分かれ、欠けの直後のチャンクの `gap`（`StreamGap`: start・samples・beat・drop_time48）に載る |

- **欠けは拍の境で始まり拍の境で終わる**（捨てるのは符号器が出した拍まるごと）。b と q だけで位置が一意に決まる。
- **時刻**（`time-accuracy` §9・§10 と矛盾しない）: 回路の符号器は欠けの間も止まらない（捨てるのは符号の後）。だから欠けの後のサンプルの
  番号 s（`StreamChunk.first`・`StreamGap.start` で数えた位置）は、止めずに流した場合と同じで、時刻の式はそのまま使える: 1 周期に複数の
  サンプルの構成は **辺 n = start_time × 8 + s × d − latency**（§7、`LaStream.sample_time(s)`）、1 周期 1 サンプルは **start_time + s ×
  (rate + 1) − LA_DEEP_DELAY − 位相の幅**（R1）。欠けの区間 [start, start + samples) の時刻も同じ式。記録の [47:0] の time は「回路が
  拍を捨て始めた周期」で、サンプルの時刻ではない（ホストは位置から時刻を出す。API には出さない）。
- **GAP_HOLD**: sys 側が hold を見るまでに、FIFO（512）と受け渡しの中にある拍（≦ 約 520）を、上書きせずに書ける余裕。**GAP_ROOM**:
  欠けを閉じてから次の欠けまでの最小の拍の数（hold の上げ下げの幅）。FIFO の「半分未満」も同じ役（FIFO が受けない欠け）。これらは
  記録の**粒度**（記録の件数が拍の流れに比べて増えすぎない）を決める回路の定数で、測った値から何かを判定する閾値ではない。捨てる
  サンプルの総数は変わらない（リングが満ちている間は PC が読む速さで決まる）。違いは、山が終わった直後に最大 GAP_ROOM 拍（64 KB、
  50 MB/s で約 1.3 ms）余分に捨てうること。返す事実（位置・長さ）は正確。
- 安全の網: それでも未読が `LA_SIZE − 256` を超えたら、今までと同じく書き込みを止めて overrun（上書きしない）。

### 12.2 案から直したこと（理由）

1. **捨てる所は「符号器の拍の出口」**（案は「sys 側の符号器が拍を捨てながら」）。符号器の中（入力の語）で捨てると、RLE の作りかけの
   レコードが欠けをまたいでつながり、長さが嘘になる。出口で拍まるごと捨てれば、符号器の状態は止めずに流した場合と同じで、時刻の式も
   変わらない。部品を符号器から分けたので、1 周期 1 サンプル（`la_encoder`）と N 並列（`la_lane_encoder`）の**同じ部品**で済み、
   符号器は変えていない。
2. **記録の位置は「流れのサンプルの位置 p」でなく「欠けの前に出した拍の数 b」**。p は欠けの前の欠けの和を回路が数え続ける必要があり、
   ホストは b（見出しの通し番号と同じ数え）と拍の解読で p を正確に出せる。回路の 40 ビットの欄は q に使う。
3. **ホストは「拍を受け取った後に読んだ件数」が揃うまで、関わりうる拍を出さない**（案に無い。正しさに要る）。欠けの記録は回路の中では
   その後の拍より先にイベントのリングへ書かれるが、流れの上ではイベントとロジアナの拍は別のかたまりで、届く順は決まらない（PS の中継は
   交互に、PL の読み戻しも交互。応答待ちの書きの除き方で、イベントの公開が拍より遅れることもある）。後から届いた記録で、出した後の
   チャンクの位置を直すことはできない。そこで CSR `gaps`（件数 N）を拍を受け取った後に読む（拍 b の前の記録は拍 b が書かれる前に
   出ているので N に入る）。届いた記録が N 件になるまで持つ。届いていない記録が 1 件なら、その位置は `gap_last_beat`（`gaps` より先に
   読む: 間に増えても位置は小さく見えるだけで安全側）なので、その前の拍は出せる。2 件以上なら、届いた最後の記録の位置より前だけ出す。
   流れの終わりに届かなかった記録の後ろの拍は出さず、`unplaced_beats` に数える（黙って位置をずらさない）。
4. **欠けを記録できないときは捨て始めずに止める**: 欠けの記録はイベントのリングに書くので、イベントの記録（`events.enable`）が切れて
   いると書かれない。捨て始める・記録を出す周期に `ev_enable = 0` なら、今までの溢れと同じく止める（overrun）。ホストは `gaps` = true の
   流れを始める前にイベントの記録をしていなければ始める（`EventLog.ensure_started`。記録中ならそのまま）。
5. **止めた時点で捨てている欠け（流れの最後）は記録しない**（`status.gap_open` = 1 が残る）。止めた後の拍は流れの外で、作りかけの拍を
   捨てる今の約束と同じ。

### 12.3 1 周期 1 サンプルの深いバッファ（`fprobe_pynq_deep`）にも要るか

**要る、同じ作りにした**（`la_stream_gap` を `la_deep_buffer` の LANES に依らない所に置いた）。理由: 溢れの原因（PC・中継が読む速さ <
信号の変化の多い RLE・速い RAW）は 1 周期 1 サンプルでも同じで、リングが満ちる。違いは 1 拍のサンプルの数だけ（LANES = 1 は `la_pack` の
語 8 つ = 8 << pack、LANES > 1 は (128 / WIDTH) << pack。どちらも 16 ch で 8 << pack）。`la_encoder` は出口が止まると拍を捨てて overrun に
するが、gaps の流れでは出口が常に受ける（in_ready = 1）ので、符号器の中では捨てない。

### 12.4 残した限界（事実として返す）

- **RLE の符号器そのものの溢れ**（`la_lane_rle` の溜め 16 レコード。毎サンプルの変化が続く = 1 周期に 4 レコードを超える変化）は、gaps の
  流れでも今までどおり止まる（overrun）。理由: 符号器の出口の速さを超える信号は、欠けの記録が数周期ごとになり、記録が拍の流れと同じ
  くらいの量になる（記録の意味が無い）。この場合は RAW のほうが小さい（§2.4）。
- イベントのリングの未読が半分に達したとき（DAP のイベントが多く PC が読まない）も今までどおり止まる。
- 欠けの記録が届かない（イベントの流れが途中で止まった）ときの拍は返さない（`unplaced_beats`）。

### 12.5 API の出力の変化（`gaps` を指定したときだけ。既定 false は今までと同じ）

- `la.stream`（`la_stream`）: 引数 `gaps`。結果に `gaps` = [{start, samples, beat}]（流れのサンプルの位置 start から samples サンプルは
  値が無い。VCD では欠けの区間の全信号が x）、`gap_samples`、`unplaced_beats`。`samples` は値のあるサンプルの数（今と同じ意味）、
  **`duration_s` は欠けを含む流れの長さ**（(samples + gap_samples) × 間隔。gaps でない流れは gap_samples = 0 で今と同じ値）。
- `recording.la_stream.start`: 引数 `gaps`。記録の stream "la" に出来事 **"gap"**（時刻 = 欠けの最初のサンプルの位置の時刻、t_end = 欠けの後の
  最初のサンプルの位置の時刻、body = samples・
  duration_ticks・beat）。波形のかたまりは欠けの前で閉じ、欠けの後から始め直す（欠けの区間に波形を置かない）。status と stream_stop の
  body に gaps（件数）・gap_samples・unplaced_beats。`stream_start` の body に gaps。
- イベント: 種類 19 は `events_read` 等で "la_gap"（address = b、value = q）として解読できる（記録の collector は二重に入れない）。
- ケイパビリティ: FEATURES bit 17、`Capabilities.la_stream_gaps`。CSR は §12.1。Python: `DeepAnalyzer.stream(gaps=)`・`stream_to_vcd(gaps=)`、
  `StreamChunk.gap`、`LaStream.gaps`、`StreamStats.gaps`・`gap_samples`・`unplaced_beats`、`GapPlacer`、`StreamGap`、`VcdWriter.gap`。

### 12.7 番号の付け替え（2026-11-02、時刻の正しさ S2 との統合）

段 B は、別の作業ツリーで並行に作られた時刻の正しさの段階 S2（`2026-11-01-time-accuracy-design.md` §12）と同じ番号を使っていた。
統合では**段 B の番号を移した**。

| 番号の空間 | S2 | 段 B（前） | 段 B（後） |
|---|---|---|---|
| イベントの種類 | 16 = PHY の設定、17 = サンプラの値を返した転送の点、18 = サンプラの誤りの区間 | 16 = `EVENT_KIND_LA_GAP` | **19** |
| FEATURES | bit16 `DAP_LINE_TIME` | bit16 `LA_STREAM_GAPS` | **bit17** |
| CSR `la_deep` | （触らない） | `control` bit16 `gaps`・`status` bit5 `gap_open`・0x4C `gap_last_beat`・0x50 `gaps` | そのまま（S1・S1b・S2 のどれとも重ならない: `control` は 0〜15、`status` は 0〜4・8〜10、レジスタは 0x48 `info` まで） |

段 B を移した理由:
- **記録の互換**: どちらも実機の記録（ファイル）はまだ無い（どちらも実機で未確認）ので、互換で縛られる記録は無い。それなら番号を
  動かす量の少ない方を動かす。S2 は 3 つの種類（16〜18）と bit を使い、RTL（`event_collector`・`dap_sampler`）・ホストの解読
  （`events`・`collector`・`timing`）・API（`events_read` の kind）・試験の多くが値を持つ。段 B は 1 つの種類で、RTL の値は
  `la_stream_gap.vhd` の定数 1 か所、ホストは `fprobe_map.EVENT_KIND_LA_GAP`・`FEATURE_LA_STREAM_GAPS` の名前で読む。
- **既存の番号の使い方**: S2 の 16〜18 は DAP の線の上の件の続き番号（種類 7 のサンプラの語の窓の後端が 17・18）で、まとまった
  並びを保つ方が読みやすい。ロジアナの欠けは DAP と別の源なので、空いている次の番号 19 に置いても意味の並びを崩さない。
- 生成物（`fprobe_gw gen`・`fprobe.api gen`）と試験（`la_stream_gap_tb`・`la_deep_buffer_gap_tb`・`test_la_stream_gaps`）は
  名前の定数で比べるので、値を変えても試験は書き換えずに通る（RTL の定数と `fprobe_map` の一致は `la_stream_gap_tb` が確かめる）。
