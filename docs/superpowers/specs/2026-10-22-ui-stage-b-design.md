# 画面に全 API を入れる・段階 B（お気に入りと専用の画面）

日付: 2026-10-22。親の仕様: docs/superpowers/specs/2026-10-22-ui-all-apis-design.md。
利用者の承認:
- 段階 B に進む（2026-10-22）。
- 「よく使うものは人によって違うので、カスタマイズできるように」（2026-10-22、利用者の案）。
  - これを受けて、お気に入りを先に作り、専用の画面は見せ方が要るものに絞る形を示した。
  - 利用者から異論は出ていない。

## 1. 目的

段階 A の API パネルで、どの操作も呼べるようになった。段階 B では、よく使う操作を速く・分かりやすくする。

- 人によって「よく使う」は違う。作り手が決めた画面を増やし続けるのではなく、人が自分で並べられるようにする（お気に入り）。
- 結果を見せ方で分かりやすくする必要がある機能だけ、専用の画面にする。

## 2. お気に入り（先に作る）

- **登録:** API パネルで、いまの引数のまま「お気に入りに追加」。名前は既定でメソッド名で、あとで変えられる。
- **呼び出し:** 新しいパネル「お気に入り」（Favorites）にボタンで並べる。
  - 押すと、API パネルと同じ確かめ（read は無し、control は確かめ、元に戻せない操作は赤）で呼ぶ。
  - 最後の結果か誤りを、そのボタンの下に出す。
- **管理:** 名前の変更・並べ替え（上へ・下へ）・削除・「API パネルで開く」（引数を直す）。
- **保存:** その人の画面のブラウザごと（localStorage、prefs.ts）。
  - 理由: 「人によって違う」ものなので、デーモン（全員で共有）には置かない。
  - 消えても困らない便利の範囲である。
- **仕様が変わったとき:**
  - 登録したメソッドが仕様から消えた場合は、ボタンを無効にして知らせる。
  - 引数が仕様に合わなくなった場合は、呼ぶ前に API パネルと同じ組み立てで確かめ、誤りを出す。

## 3. 専用の画面（見せ方が要るもの。この順に作る）

| 順 | 機能 | 置き場所 | 専用にする理由 |
|---|---|---|---|
| 1 | 接続の失敗の理由（target.diagnose・probe.pins.read） | 接続のダイアログ。失敗したら診断の手順を表で見せ、提案の設定を欄に入れる | 失敗したその場で、手順ごとの事実を見せる |
| 2 | 故障の状態の保存（snapshot.*） | Fault に「保存」、Recordings に「保存済みの状態」の節（一覧・開く・閉じる） | 一覧と、開いている状態の表示が要る |
| 3 | ロジアナの保存（la.export） | LogicAnalyzer のバーに「保存」（形式 sr / vcd） | ロジアナの画面で当然あるべきボタン |
| 4 | 故障の直前の命令（trace.etm.*） | Fault に「直前の命令」の節（decode の後に history） | 命令の並びを関数・行つきで見せる |
| 5 | スタックの使用量（target.stack.*・rtos.timeline.memory） | Threads に、塗りによる MSP の使用量の行と、スレッドごとの最大の使用量 | 棒で見せる |
| 6 | ヒープ（heap.scan・heap.trace.*） | 新しいパネル「Heap」 | 使用量・断片化・二重の free・呼び出し元ごとの表 |
| 7 | 2 点の間のサイクル数（cycles.measure・cycles.read） | Source の行・Disassembly の番地で始点・終点を選び、結果をバーに出す | 場所を画面で選ぶ |
| 8 | ログ（log.*） | Terminal の源に「log」を足す（defmt / trice 等） | 端末と同じ流れで読む |
| 9 | 保護（target.option_bytes.*・target.unlock） | Flash に「保護」の節（読む・名前ごとの値と説明・書く・解除） | 値の意味（説明）を並べて見せる |

DAP の直接の読み書き（target.dp.* / target.ap.*）は専用の画面を作らない。引数を入れて呼ぶだけなので、お気に入りで足りる。

## 4. 共通の決まり

- 画面の判断を入れない（CLAUDE.md）。結果は API が返した事実をそのまま並べる。並べ替えや強調は、値そのもの（誤り・overflow 等、API が返した印）でだけ行う。
- 状態を変える操作は、API パネルと同じ確かめにする（allowed・confirmer）。
- 処理は `lib/*.ts` に出し、FakeConn で試す（このリポジトリの形）。画面は Chrome で実際に動かして確かめる。
- 文言は i18n.ts の EN と JA の両方に置く。

## 5. やらないこと

- お気に入りをデーモンや AI と共有すること（必要になったら別に決める）。
- 段階 B の画面に、API に無い計算を足すこと（足すなら API の側に）。
