# ロジアナの垂れ流しで、使うチャンネルだけ詰める（la_pack）

2026-10-31。利用者の指示（「情報を捨てる方針は無し。それ以外は、効果がある見込みならやるべき」）で、PYNQ-Z2 の垂れ流しの壁（約 50 MB/s）の下で、
速いサンプルレートを流すために作った。経緯と測定の流れは `2026-10-30-la-stream-ps-direct-design.md` の 10.8〜10.16 節。

## 1. なぜ

PYNQ-Z2 の PS 直読みの垂れ流し（RAW、16 ch）は、2 バイト/サンプルで、リンクが持続できるのが約 50 MB/s（25 MS/s）。それ以上の速さで流す手は、
次のどれかになる。

| 手 | 欠け | 見立て |
|---|---|---|
| 間引き | 情報を捨てる | **採らない**（利用者の方針） |
| RLE（実装済み） | なし | 変化の少ない信号だけ。変化が毎サンプルだと 2 倍に増える |
| 汎用の圧縮を PL に入れる | なし | 作業が大きく、効果が信号次第で読めない |
| **使うチャンネルだけ詰める** | **選んだチャンネルは欠けない** | データ量が 1/2・1/4・1/8。信号に依らず効く |

深いバッファのストリームは、sys（100 MHz）の 1 サンプル/周期が上限（`2026-10-30-la-capture-clock-design.md`: 300 MHz の恩恵は無い）。4 ch なら 100 MS/s でも
0.5 バイト/サンプル = 50 MB/s で、いまの壁に収まる。

## 2. ゴール・非ゴール

- ゴール: 8・4・2 ch（ch 0〜n − 1）だけを、欠けなしで、データ量 1/2・1/4・1/8 で流す。選んだチャンネルは 1 サンプルも欠けない。
- ゴール: 既定は今のまま（16 ch、詰めない）。詰めるのは、使う人が `pack_channels` で明示したときだけ（既定の暗黙の値にしない。CLAUDE.md）。
- ゴール: エンコーダ・DDR のリング・PS の中継・TCP の経路は変えない。
- 非ゴール: 任意のチャンネルの組を選ぶこと（ch 0〜n − 1 だけ。上位のチャンネルは記録されない）。トリガ取り込み（RAW の捕捉）で詰めること（トリガの位置の精度を使うため。垂れ流しだけ）。
  RLE との併用（RLE は 16 ビットの値の繰り返し）。

## 3. 形

- 回路: `rtl/la/la_pack.vhd`（ボード非依存、sys ドメイン）。エンコーダ（`la_encoder`）の手前に置く。`pack` = 0〜3 で、1 サンプル 16・8・4・2 ビットとし、連続する 1・2・4・8 サンプルを
  1 つの 16 ビットの語にする（時間の古いサンプルが下位。エンコーダの RAW の拍と同じ向き）。`pack` = 0 は入力をそのまま通す（待ち 0 周期）。run = 0 の間は作りかけの語を捨てる。
  RLE のときは詰めない（`la_deep_buffer` が `pack_eff` を 00 にする）。
- レジスタ: `la_deep.control.pack`（ビット 5:4、RW、run の間は変えない）。ケイパビリティ `la_pack`（FEATURES ビット 12）。外部メモリ（深いバッファ）のある構成だけ。
  今は `fprobe_pynq_deep` だけが持つ（Primer の構成は、再ビルドと実機の確認が要る）。
- ホスト: `DeepAnalyzer.stream(pack_channels=8|4|2)`。8・4・2 以外・rle との併用は `ValueError`、ケイパビリティが無い構成は `RuntimeError`（黙って詰めない）。
  `StreamChunk.pack` で、`samples()`・`length`・`transitions()` を、語ごとでなくサンプルごとに展開する。`LaStream` のサンプル数は語数 × 2^pack。
  `stream_to_vcd`・デーモンの API `la.stream`・`recording.la_stream.start` に `pack_channels`。VCD と記録のチャンネル数は、詰めた数（上位は出ない）。
- 画面: System Analysis の Start Recording で、Format = RAW のとき、レート（MS/s）とチャンネル数（16・8・4・2）の選択が出る（必須。空のままは開始できない。画面で既定を決めない）。
  画面は引数を組み立てるだけで、計算・判定を持たない（MS/s → Hz の書き換えと、必須の欄の確認だけ）。

## 4. 確かめ方

- シミュレーション（cocotb）: `la_pack` 単体（pack 0 の素通し・8/4/2 ビットの詰め・トリガの語・run = 0 での作りかけの破棄）。`la_deep_buffer` を通して、8・4・2 ビットのカウンタが、
  展開すると欠けも重複もなく 1 ずつ増える（受け手が止まる条件つき）。
- ホスト（偽のデバイス）: 指定の検査、制御レジスタへの書き込み、語の展開、変化点、VCD のチャンネル、記録（`LaRecordingStream`）への着地。画面の関数（`pinsStreamStart`）は vitest。
- 実機（PYNQ-Z2、`fprobe_pynq_deep`。欠けなし = overrun なし・lost_frames 0・サンプル数がレート × 時間と一致）:

  | 構成 | データ量 | 長さ |
  |---|---|---|
  | 16 ch・25 MS/s | 50 MB/s | 60 秒を 11 回 |
  | 8 ch・50 MS/s | 50 MB/s | 60 秒を 2 回（各 3,015 MB） |
  | 4 ch・100 MS/s | 50 MB/s | 60 秒を 2 回（各 3,015 MB） |
  | 2 ch・100 MS/s | 25 MB/s | 20 秒 |
  | 8 ch・25 MS/s | 25 MB/s | 10 秒 |

  実機の試験: `gateware/tests/hil/test_pynq_ps_stream_hw.py` の `test_packed_stream_keeps_every_sample_at_the_rate_the_unpacked_stream_cannot_reach`。
  画面と同じ道（記録の開始 → 垂れ流しの開始）でも、8 ch・50 MS/s を 5 秒、溢れなしを確認した。

## 5. 限界・未確認

- 実機の入力は、何もつないでおらず（信号は一定）、**中身の並びの確認はシミュレーションのみ**。実機の確認には、ch 0〜7（PMOD JA）に既知の信号が要る
  （JA は SWD・JTAG の線と兼用なので、駆動の衝突に注意）。
- 時間無制限の持続は、理屈（速度が一定で、受け取りの上限以下ならバッファは溜まらない）と、60 秒の実測まで。
- 50 MB/s の構成は、PYNQ の 2 コアの余裕が小さい（約 15 %）。長時間・PC が忙しいときは、25 MB/s の構成（2 ch・100 MS/s、8 ch・25 MS/s）のほうが安全。
