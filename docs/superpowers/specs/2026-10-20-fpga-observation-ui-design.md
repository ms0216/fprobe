# FPGA 観測の PC ツール（U1）— 共通の時間軸に「FPGA の中」を並べる

2026-10-20。利用者の依頼:「同じようなツールの UI/UX を参考にしつつ、それらに追いつき、追い越す PC ツールにしてほしい」。
利用者は質問を飛ばして「とりあえず始めて」と言ったので、下の決めごとは**私の判断**（§7 に一覧）。違っていれば直す。

参考: docs/reference/fpga-debug-tools-ux.md（Vivado ILA・Signal Tap・GAO・EXOSTIV・TRACE32・Saleae 等の比較）、

## 1. 狙い

既存のツールは、FPGA の内部を「内蔵メモリの短い窓」に取り込み、ベンダーごとの別の画面で見る。MCU の内部・FPGA の内部・
基板の線を 1 本の時間軸に並べられるものは無い（調査）。fprobe はそれを JTAG だけでできる（O2 で ±6 ns の揃え方を確認）。

U1 では、それを人間と AI が使える形にする:

1. FPGA の観測の値が、**ロジアナ・DAP・UART・RTOS 等と同じ時間軸の段**に並ぶ（記録しながら・後から）。
2. 16 ビットの組に**信号の名前・ビットの範囲・列挙の名前**を付け、段はその単位で見える（状態機械が状態名で見える）。
   **後から付けた名前も、過去の記録に効く**（Vivado の ILA はできない）。
3. **記録が途切れた所（溢れ）・観測する組を切り替えた所**が、時間軸にはっきり出る（黙って欠けない）。
4. 画面のパネルで、つなぐ（鎖の位置・USER の命令・TCK）→ 申告（ID・組の数・遅れ）を見る → 組を選ぶ → 記録、ができる。
5. AI（MCP）も同じ定義で同じ名前を見る（画面と AI で信号の名前を共有する）。
6. 書き出し（VCD）に FPGA の信号も入る（GTKWave・PulseView で開ける）。

## 2. 作らないもの（U1）

- 条件で記録の中を探す・後からトリガを評価する（調査の「勝てる点 5」）→ U2。
- 信号の候補を RTL から探す（観測の回路の組の割り当ては対象の FPGA の設計者が決める。U1 は名前を付けるだけ）→ U2 以降。
- 複数の観測の回路・複数の鎖（1 つの観測の口に 1 つの対象）。
- TDO の取り込みの点の調整（R16）。

## 3. データの形（真実は 1 か所）

- **記録（recording）には組の生の値だけを入れる**: stream `fpga`。
  - `value`: t = 値が変わった瞬間の fprobe の時刻（申告の遅れで直した後）、a = 組の番号、b = 16 ビットの値。
  - `gap`: t = 再開した時刻、a = 失った値の変化の数（観測の回路の溢れ）。
  - `group`: t = 組を切り替えた時刻、a = 新しい組（観測の回路の SELECT。段の帯「どの組を記録していたか」）。
  - 組の番号は**観測の回路が記録の列に入れる**（PC が select を呼んだ時刻からは、溢れの再同期と区別できず正確に
    決まらない）: 種類 1（時間）の記録は delta に 14 ビットしか使わないので、bit 29 = 1 を「制御の記録」にする
    （bits 28:24 = 種類、0 = 組の番号 bits 7:0）。再同期（開始・溢れの後・組の切り替え）は
    「（溢れ）→ 組 → 絶対 → 値」の順に書く（FIFO の空きは 4 語を待つ）。
  - 時刻合わせ（イベント 9）が無い間の値は時刻が決まらないので入れない（fpga_obs.samples と同じ）。
- **取り込みは少しずつ**（Collector は 0.2 秒ごとにイベントを読む。流し続けの間は流れが読む）。fpga_obs に状態を持つ
  復号器 `ObsDecoder`（時刻合わせの区間・今の対象の時刻・溢れ）を置き、`samples()` はその上に載せ直す
  （両者が同じ結果になることを試験で確かめる）。時刻合わせの組が 2 つ未満の間は、観測の回路の申告 CLOCK_HZ と
  タイムベースの比を仮の傾きにする（後の組で直線を当て直すが、記録済みの値は動かさない → 誤差は最初の数十 ms だけ）。
- **信号の定義**（`FpgaSignals`）: 組ごとに信号の並び。信号 = 名前・最下位ビット・幅・書式（hex / dec / bin / enum）・
  列挙（値 → 名前）。置き場所は**記録の付帯情報（meta）`fpga.signals`**（記録ごとに残る。後で開いても同じ名前）と、
  **デーモンの画面の状態 `ui.state` の `fpga_signals`**（記録していないときの既定。画面の別の窓・AI と共有）。
  記録を始めるとき、ui.state の定義を meta に写す。記録の後で変えたら meta を書き換える（過去の記録に効く）。
- **時間軸の段は、見るときに定義から作る**: 組の生の値の出来事を、定義の信号ごとの段に展開する（1 ビットは state の
  帯、幅のある信号は values の階段 + 文字、列挙は state の帯に名前）。定義の無い組は「組の値（16 進）」の段 1 本。
  時間軸の要約（ズームアウトの SQL）も同じ展開を SQL の式（`(b >> lsb) & mask`）で行う。

## 4. 画面

- **パネル「FPGA 観測」**（registry に登録）:
  - 接続: 鎖の位置（ir_len・前後の IR・前後の装置の数）、USER の命令、TCK（MHz で選び、半周期に直す。上限 12.5 MHz と
    表示）、1 スキャンの語数、時刻合わせの間隔。[つなぐ] / [切る]。
  - 申告: ID・版・組の数・FIFO の深さ・対象の clk・遅れ（写し取り・記録）。状態: 動作中・答えない（stuck）・溢れ・
    スキャンの数。答えないときは、鎖の位置・USER の命令・配線を確かめるよう案内する（ID の値も出す）。
  - 組の選択（0〜groups − 1）と、記録の開始 / 停止（観測の回路の CONTROL）。
  - 信号の表: 組ごとに、名前・ビット（例 7:4）・書式・列挙（「0=IDLE, 1=RUN …」）を編集。ビットの重なり・範囲外は
    その場で知らせる。保存すると時間軸の段がすぐ変わる（過去の記録にも）。
  - 今の値: 最後に受けた組の値を信号ごとに（列挙は名前で）。
- **時間軸**: まとまり「FPGA」（stream fpga）。信号ごとの段。`gap` は赤い印（失った数）、`group` は組を切り替えた所の印。
  縦線の値は列挙の名前・書式どおり。
- 文言は i18n（日本語・英語）に足す。

## 5. AI（MCP）と API

- `fpga_obs.signals_get` / `fpga_obs.signals_set`（定義の読み書き。記録中なら meta にも）。
- `fpga_obs.read` は、定義があれば値を信号ごとに分けて名前で返す（`fields: {名前: 値 or 列挙名}`）。
- 既存の `recording.export` の VCD に、FPGA の信号を `$var wire <幅>` で書く。

## 6. 試験

- Python: ObsDecoder を少しずつ与えても全部を一度に与えても同じ・Collector が種類 8・9 で止まらず `fpga` の行を入れる・
  信号の定義の検査（重なり・範囲）・段の展開（Python と SQL が同じ段と値）・VCD に信号が入る・API の表の一致。
- 画面（vitest）: 信号の表の解釈（「0=IDLE, 1=RUN」→ 列挙）と検査、TCK ↔ 半周期の換算、パネルの状態の表示の文言。
- 実機: 記録しながら観測（Primer の代役）→ 時間軸の `fpga` の段に、名前を付けたカウンタの信号が出る（HIL）。

## 7. 私の判断（利用者が質問を飛ばしたので）

1. 新しい画面を別に作らず、既存の Svelte + dockview の画面の**時間軸に統合**する（勝てる点「1 本の時間軸」に直結）。
2. 記録には生の値だけ、名前は付帯情報に置いて見るときに展開する（後から付けた名前が過去に効く。真実が 1 か所）。
3. 信号の定義は記録の meta と ui.state の 2 か所（記録の中で完結 + 画面・AI の共有）。
4. 条件での検索・後からのトリガ・RTL からの信号の候補は U2 以降。
5. 時刻合わせが 2 組そろう前の値は、申告の CLOCK_HZ の仮の傾きで時刻を付ける（記録済みの値は動かさない）。
6. 組の番号は観測の回路の記録の列に入れる（種類 1 の bit 29 = 制御の記録）。観測の回路の形式を足すが、版はまだ
   出していないので VERSION 1 のまま。
