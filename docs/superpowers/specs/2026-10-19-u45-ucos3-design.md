# U45 RTOS の対応の拡大（続き）: µC/OS-III

ThreadX（`2026-10-18-u45-threadx-design.md`）に続いて、U45 の **µC/OS-III** を足す。µC/OS-III のヘッダは Apache-2.0
（MIT ではない）で、ThreadX のときは保留したが、RTX5 と同じく Apache-2.0 のヘッダを出典とライセンスを SOURCE.md に書いて
取り込んでよい、と判断した（利用者、2026-10-18）。

## 1. 試せる本物

GitHub の weston-embedded/uC-OS3 v3.08.02 と、そのヘッダが含める uC-CPU v1.32.01・uC-LIB v1.39.01（どれも Apache-2.0）。
ヘッダ（os.h・os_type.h・ARMv7-M の GNU の port の os_cpu.h・cpu.h 等）を `host/firmware/ucos3_shape/ucos3/` に取り込み、
出典・ハッシュ・ライセンス（LICENSE・NOTICE）を `SOURCE.md` に書いた。設定 `os_cfg.h` はテンプレートの写しで、
OS_CFG_DBG_EN だけを変えられるようにした（Apache-2.0 の 4(b) の印をその先頭に）。

## 2. 口（既存の層に合わせる）

`fprobe.rtos.ucos3.UCOS3`（`KernelAwareness`）を `open_rtos` の表に足す（`detect` は `"ucos3"`、`name` は `"uC/OS-III"`）。
API・MCP の `rtos.*` は RTOS に依らないので、そのまま µC/OS-III で動く（summary の種類の列を更新）。

- 検出: 大域変数 `OSTCBCurPtr`・`OSRdyList` と型 `OS_TCB`（`PendObjPtr`・`StkPtr`）。µC/OS-II（`OSTCBCur`）とは別。
- タスクの一覧: OS_CFG_DBG_EN のときは `OSTaskDbgListPtr`（`DbgNextPtr` の列。NULL で終わる。数は `OSTaskQty`）。
  輪になる・多すぎる・数が合わないときは警告する。OS_CFG_DBG_EN が 0（テンプレートの既定）なら一覧が無いので、
  OS_TCB の変数（大域・static）・準備完了の列 `OSRdyList[]`・時間の列 `OSTickList`・実行中から集めて、番地の順に並べる
  （警告。動的に確保した TCB で、時間切れの無い待ち・停止中のものは漏れうる）。
- 名前: `NamePtr`（DBG のとき）→ 変数のシンボル → 番地。
- 実行中: `OSTCBCurPtr`（状態が RDY のとき）。
- 状態（`TaskState` のビット DLY・PEND・SUSPENDED）: RDY → running / ready、DEL（255）→ deleted、SUSPENDED のビット →
  suspended（遅延・待ちも重なっていれば wait にそれを出し、notes に `SuspendCtr` の入れ子）、それ以外 → blocked。
- 待ち（`PendOn`）: SEM・MUTEX・Q・TASK_Q → receive、FLAG → event、COND → pend、TASK_SEM → notification。
  待つもの `PendObjPtr` の種類は先頭の `Type`（"SEMA"・"MUTX" 等の 4 文字）で確かめる。タスクに組み込みのセマフォ・
  キューは待つオブジェクトが無い（kind task_semaphore / task_queue）。ミューテックスなら持ち主（`OwnerTCBPtr`）。
  µC/OS-III のキューは送り手を待たせない（満杯なら OSQPost が失敗する）ので、送りの待ちは無い。
- 残りのティック: `OSTickList` の差分の列（`TickRemain` は前のタスクからの差。os_tick.c）の先頭から自分までの和。
- 優先度: 小さい方が高い（`priority_order = -1`）。元の優先度は `BasePrio`（ミューテックスの継承の前）。
- スタック: `StkBasePtr` から `StkSize` 語（CPU_STK の大きさは DWARF の型から）。`Opt` に OS_OPT_TASK_STK_CLR があれば全体が
  0 なので、0 の残りで最大の使用量、底が 0 のままでなければあふれ（notes）。無ければ塗りが無い（fill = none）。
  StkBasePtr・StkSize は OS_CFG_DBG_EN・STAT_TASK_STK_CHK_EN・TASK_STK_REDZONE_EN のどれかで入る（どれも無ければ範囲は不明）。
  レッドゾーン（OS_CFG_TASK_STK_REDZONE_EN。テンプレートは 0）の深さは DWARF に出ないので、今回は扱わない。
- 保存された文脈: `StkPtr` から。ARMv7-M の port（os_cpu_a.S）は r4〜r11、EXC_RETURN、[s16〜s31]、ハードのフレーム、
  ARMv6-M は r4〜r7、r8〜r11、EXC_RETURN、ハードのフレームで、どちらも `cortexm.read_saved_context` の `"armv7m_fp"`
  と同じ並び（新しい積み方は要らない）。`rtos_info` の `port` は ELF の `Tag_CPU_arch` から armv7m / armv6m。
  巻き戻しは `OS_TaskReturn`（OSTaskStkInit が最初の LR に置く）で止める。
- オブジェクト（`fprobe.rtos.ucos3_objects`）: 次の 3 つを合わせる（同じ番地は 1 つ）。
  1. OS_CFG_DBG_EN のときの種類ごとの一覧（`OSSemDbgListPtr`・`OSMutexDbgListPtr`・`OSQDbgListPtr`・`OSFlagDbgListPtr`・
     `OSMemDbgListPtr`・`OSTmrDbgListPtr`。数は `OS*Qty`）。Type が違うものは警告して外す。
  2. 型がオブジェクトの構造体か、それを指すポインタの変数（OS_CFG_DBG_EN が 0 でも見つかる。まだ作っていない・消した
     ものは Type が違うので黙って外す）。変数の名前は aliases（カーネルの `OS*Ptr` は外す）。
  3. タスクが待っているもの（`OSTmrCond` のように一覧に無いカーネルのものも）。
  種類: semaphore（count）・mutex（持ち主・継承・入れ子の数。µC/OS-III のミューテックスは必ず継承する）・
  queue（count・max_msgs、DBG のときは peak）・event_flags（flags）・memory_pool（ブロックの大きさ・数・空き）・
  timer（state・周期・遅れ・残り・呼ぶ関数と引数）・cond（結びついたミューテックス）。待ち手は `PendList`
  （`PendNextPtr`。優先度順）。イベントフラグの待ち手は待つビット・all・clear（CONSUME）・on_clear（消えるのを待つ）。
- タイマの残り: `OSTmrRemainGet` と同じく `OSTmrListPtr` の差分（`Remain`）を自分まで足し、時間のタスクがまだ反映して
  いない経過（`OSTickCtr − OSTmrTaskTickBase`）を引く（OS のティック。Dly・Period も OSTmrCreate が OS のティックにする）。
- サンプラ（時間軸・逆転の推移）: いまのタスクの語 `OSTCBCurPtr`、保存された SP `StkPtr`、ミューテックスの
  `OwnerTCBPtr`・`PendList.HeadPtr`（差 0、空は 0）。アイドルは `OSIdleTaskTCB`。
- スケジューラ: `OSRunning` が RUNNING でなければ not_started、`OSSchedLockNestingCtr` なら suspended、ほかは running。
  版は `OSDbg_VersionNbr`（os_dbg.c。DBG のとき。30802 → "3.08.02"）、ティックは `OSTickCtr`。
- ヒープ: µC/OS-III にシステムのヒープは無い（OS_MEM の区画がその役。オブジェクトとして出す）。`heap()` は None。

## 3. 試験

`host/firmware/ucos3_shape/`: 本物のヘッダの構造体とカーネルの変数で、止めたときの様子を .data に置いた ELF
（arm-zephyr-eabi-gcc、Cortex-M4F。µC/OS-III のカーネルそのものではない）を OS_CFG_DBG_EN = 1（`ucos3_shape.elf`）と
0（`ucos3_shape_nodbg.elf`）で 2 つ作る。`host/tests/test_rtos_ucos3.py` が、12 のタスク（実行中・準備完了・セマフォの
時間切れ付きの待ち・遅延・ミューテックス待ち（継承した持ち主）・停止・キュー・イベントフラグ・タスクのセマフォ・遅延中の
停止・カーネルの時間のタスク（条件変数）とアイドル）、差分の列からの残りのティック、0 の塗りと壊れた底・塗らないタスク、
FP の有無の文脈と巻き戻し、オブジェクト（タイマの未反映の経過・条件変数・カーネルのミューテックスの名前と変数の名前）、
継承と逆転、壊れた列と数の違い、一覧の無い設定での集め方を確かめる。
