# PC 側 第 3 段: 人間用の画面 v1 設計

## 1. ゴールと完了条件

ブラウザで開く画面から、AI の作業を見て、必要なら一時停止して交代し、プローブとターゲットの状態を見る。
画面はデーモン（第 2 段）の API の利用者の 1 つで、AI（MCP）と同じ API を使う。第 4 段（デバッガ）・第 5 段（波形）は
この画面にタブとして足す。

| 完了条件 | 検証 |
|---|---|
| `fprobe-daemon` が画面を配り、起動時に画面の URL を表示する | 単体（Python） |
| AI の操作が 1 件ずつ流れて見え、行を選ぶと引数・結果の詳細が出る。このデーモンの起動以降の記録をさかのぼれる | 単体（TS）+ 結合 |
| 一時停止 → AI の要求が保留され、その数が見える → 画面からターゲットを操作 → 再開で AI に戻る | 結合（偽の機器） |
| 接続している機器、プローブのケイパビリティ、ターゲットの状態・電圧、つながっている利用者が見え、変化に追従する | 単体（TS）+ 結合 |
| デーモンが落ちても画面は「切断」を示し、戻れば自動でつなぎ直す | 単体（TS） |
| 実機: AI（MCP）が作業している様子を画面で見て、一時停止・交代できる | HIL（手動の確認を報告に残す） |

非目標（後の段）: デバッガの画面（ソース・ブレークポイント・変数、第 4 段）、波形の表示（第 5 段）、UART・SWO の端末、
デスクトップアプリ化（Tauri）、複数のデーモンの切り替え。

## 2. 判断

| 判断 | 理由 | 誤っていた場合のコスト |
|---|---|---|
| TypeScript + Svelte 5 + Vite | 小さく読みやすい。Tauri はブラウザの画面をそのまま包むので、後でデスクトップアプリにしても書き直さない | 中（部品の書き直し。API との境界の層は残る） |
| 型は API の仕様から生成した `host/api/generated/fprobe_api.ts` を使う | 画面と API の食い違いを型検査（`svelte-check`）で見つける | 低 |
| 画面のソースは `host/ui/`、ビルドの出力 `host/ui/dist/` は git に入れない。デーモンは dist があれば配り、無ければビルドの手順を示す 1 枚を返す | 生成物を二重に持たない。使うのはこの PC（Node.js v24 あり）で、`pip install -e` の運用 | 低（配布が要るときにパッケージへ同梱する） |
| 画面の状態の処理（API の利用者・状態の保持）は Svelte に依らない素の TypeScript のモジュールにし、部品は表示だけ | 状態の処理を単独で試験でき、別の仕組みへ移すときも残る | 低 |

## 3. 構成

```
host/ui/                      Vite + Svelte 5 + TypeScript（npm run dev / build / test / check）
  src/lib/api.ts              DaemonConnection: WebSocket・JSON-RPC・hello・購読・自動のつなぎ直し（型は生成物）
  src/lib/state.ts            画面の状態: 機器・操作権・利用者・ターゲット・記録（通知と応答から更新）
  src/lib/format.ts           記録の行の表示用の整形（時刻・要約・所要時間）
  src/App.svelte              枠: 上の帯 + タブ（v1 は「作業」だけ）
  src/components/             StatusBar / ActivityList（詳細を含む）/ TargetPanel / ProbePanel（利用者を含む）
  tests/                      Vitest（単体: 偽の WebSocket。結合: host/tests/fake_daemon.py を起動）
fprobe-daemon                 GET / と /assets/* で host/ui/dist を配る。/api は従来どおり
```

画面の配置:

```
┌ fprobe ─ USB 0001 ─ ● つながっている ── [AI 作業中] ── 保留 0 ── [一時停止] ┐
│ 作業 | (デバッガ) | (波形)                                                    │
├───────────────────────────────────────────────┬─────────────────────────────┤
│ 記録（新しいものが下、追従。止めて読める）    │ ターゲット                  │
│ 12:01:03 claude  target.halt   0.01 s  停止   │  状態 HALTED  pc main+12    │
│ 12:01:04 claude  debug.variable.read  …       │  電圧 3.29 V                │
│ ▶ 選んだ行の詳細（引数・結果・誤り）          │  [接続][停止][再開][リセット]│
│                                               │ プローブ（ケイパビリティ）  │
│                                               │ 利用者: claude(ai), gui     │
└───────────────────────────────────────────────┴─────────────────────────────┘
```

## 4. デーモンに足すもの（API の版は 1 のまま。足すだけなので互換）

| 追加 | 内容 |
|---|---|
| `session.activity.list`（read） | 引数 `before`（記録の番号、省略で最新）・`limit`（既定 100、最大 500）。このデーモンの記録ファイルから、番号の小さい順に返す |
| 通知 `clients` | 利用者が名乗った・去ったとき、利用者の一覧（id・名前・種類） |
| 通知 `target.state` を送る | 見張り: 操作（control）が終わるたびと、1 秒ごとに `target_status` を作業スレッドで読み、前と違えば送る。ターゲット未接続なら `{"state": "DISCONNECTED"}`。見張りの読みは記録しない。一時停止中も動く（read と同じ扱い） |
| 画面の配信 | `/` と `/assets/*`。起動時に `画面: http://127.0.0.1:7820/` を表示（`--lan` ならトークン付きの URL） |

- 画面は `hello` で `role: "human"`、名前 `gui` を名乗る。トークンは URL の `#token=...` から読む（サーバの記録に残らない
  ように、クエリでなくフラグメント）。
- Origin の検査（第 2 段）はそのまま。画面はデーモン自身が配るので通る。開発中の `npm run dev`（別ポート）からは、
  Vite の代理（proxy）で `/api` をデーモンへ流して同じ生成元に見せる。

## 5. 画面の振る舞い

- **記録:** 開いたときに `session.activity.list` で最新 100 件、上へスクロールすると古いものを読み足す。以後は
  `activity` 通知を足す。いちばん下を見ているときだけ新しい行に追従する。誤りの行は色で分ける。行を選ぶと詳細
  （引数・結果の要約・誤り・所要時間）。利用者で絞り込める。
- **操作権:** `control` 通知で帯を更新（作業中 / 一時停止中（誰が）/ 保留の数）。ボタンは一時停止 ⇄ 再開。
- **ターゲット:** `target.state` 通知で状態・止まった場所を表示。ボタン: 接続（ターゲット名・周波数を入力、既定
  `stm32f401xe`・4 MHz、ブラウザに覚える）、停止、再開、リセット、電圧の再読み。画面の操作も記録に流れる。
  AI の作業中に押すと、AI の操作と混ざる旨の確認を出す（一時停止中は出さない）。
- **プローブ:** 開いたときに `probe.info`（ケイパビリティ）と `session.status`（機器・利用者）を読む。利用者は `clients` で更新。
- **つなぎ直し:** 切れたら帯を「切断」にし、1 → 2 → 4 → … 最大 10 秒の間隔でつなぎ直す。つながったら状態を読み直し、
  記録は最後に見た番号より後を読み足す（デーモンが再起動して番号が戻ったら読み直す）。
- 誤りの応答は画面の端に短く出す（コードと文言）。

## 6. 試験

- **TS 単体（Vitest）:** DaemonConnection（hello・要求と応答の対応・通知の振り分け・誤り・つなぎ直し、偽の WebSocket）、
  状態（通知の順序・記録の読み足しと重複の除去・番号の戻り）、整形。
- **型:** `svelte-check` で生成した型と画面の呼び出しの一致を確かめる。生成物と仕様の一致は既存の Python の
  試験（`write_all(check=True)`）が守る。
- **結合（Vitest）:** 試験の準備で、偽の機器（`host/tests` の FakeBackend と同じもの）のデーモンを Python で起動し、
  TS の DaemonConnection と状態を使って: 記録が流れる、一時停止で AI 役（Python の DaemonClient）の要求が保留され
  数が見える、画面から操作できる、再開で AI の要求が通る、`clients`・`target.state` が届く。
- **Python 単体:** 画面の配信（dist がある / 無い）、`session.activity.list`、`clients` 通知、`target.state` の見張り
  （変化したときだけ送る・未接続・記録に残らない）。
- **HIL:** 実機で MCP（AI）と画面を同時に使い、一時停止・交代を確かめて、結果を報告に残す。
