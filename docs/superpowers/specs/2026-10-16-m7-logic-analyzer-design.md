# M7: ロジックアナライザ（内蔵 BSRAM バッファ）設計

- 日付: 2026-10-16
- 親: `2026-10-15-fprobe-architecture-design.md` §4.3

## 1. ゴールと完了条件

| 完了条件 | 測り方 |
|---|---|
| 16 チャンネル（J12 の 8 本 + 内部信号）を最大 100 MS/s（sys クロック）で取り込み、トリガ前後の波形を PC に取り出せる | シミュレーション + HIL |
| トリガ: 値一致（マスク付き）と各チャンネルの立ち上がり / 立ち下がり。プリトリガ量を指定できる | シミュレーション |
| トリガ時刻を共通タイムベースで記録し、VCD に出せる（PulseView 等で表示） | HIL: pyOCD の SWD 通信を取り込んで VCD |

## 2. 構成

- `la_capture`（`rtl/la/`、ボード非依存、sys ドメイン）: 入力の同期化（2 段）、サンプル間隔（`rate` + 1 周期ごと）、
  トリガ判定、リングバッファ（BSRAM、DEPTH 語 × WIDTH）、捕捉の制御、読み出しポート。
  - 状態: 停止 → プリトリガを溜める → トリガ待ち（リング）→ トリガ後を溜める → 完了。`run` の 0→1 で開始、
    1→0 で中止。
  - トリガ = （(サンプル and mask) = (value and mask)）かつ（エッジ指定があれば、指定したチャンネルのどれかがその向きに変化）。
    指定が何もなければすぐトリガ。外部トリガ入力（M9 のクロストリガ用）も OR で受ける。
- CSR `la` ブロック（設定・状態）と `la_mem` 窓（バッファを 1 サンプル = 1 ワードで読む）。
- チャンネル: 0〜7 = J12（pmod1）のピンの値、8 = SWDIO をプローブが駆動中、9 = DAP コマンド処理中、10〜15 = 0（予約）。
- ケイパビリティ: `LA_CHANNELS`、`LA_DEPTH`、`LA_SAMPLE_HZ`（最大サンプルレート）。
- ホスト `fprobe.la`: 設定・開始・完了待ち・読み出し・VCD 出力。

## 3. 判断

| 判断 | 理由 | 誤っていた場合のコスト |
|---|---|---|
| サンプルは sys クロック（100 MHz）で取る（専用の高速サンプルクロックは使わない） | M7 では BSRAM の深さ（8192）がボトルネックで、100 MS/s で十分。DDR3（M8）と一緒に高速化を検討 | 低 |
| 読み出しは CSR 窓（CONTROL チャンネル）で行い、CAPTURE ストリーム EP は M8 のストリーミングで使う | 8192 サンプルなら数十 ms で読める。仕組みを増やさない | 低 |
| 圧縮（変化点符号化）は M8 | 内蔵バッファでは効果より複雑さが勝る | 低 |
