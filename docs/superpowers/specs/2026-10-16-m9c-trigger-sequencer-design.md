# M9 第 3 段: 多段トリガ（トリガシーケンサ）設計

## 1. ゴールと完了条件

「A の後 T 以内に B」「X が N 回目」のような順序・回数・時間の条件で、ロジアナのトリガやターゲット停止を
ハードウェアだけで発火する（ホストの往復なし。判定は sys の 1 周期 = 約 10 ns 単位）。

| 完了条件 | 検証 |
|---|---|
| 2 つのパターン（値・エッジ）と DAP の番地一致・ホスト指令を条件に、最大 4 段の順序・回数・制限時間で発火する | cocotb（trig_seq 単体） |
| 発火をクロストリガの新しい源 `SEQ`（bit3）としてロジアナのトリガ・割り込み書き込みへつなげる | cocotb + HIL |
| 実機: 「UART 送信の立ち下がり 2 回目」で深いバッファをトリガし、トリガ位置が 2 回目の立ち下がりに一致 | HIL |

## 2. 構成

```
ピン（2 段で同期化）─→ パターン A / B（mask・value・rise・fall、la_front と同じ意味）─┐
DAP の番地一致（xtrig）、ホスト指令 ─────────────────────────────────────────────┴→ 段 0..3 → SEQ（1 周期）
```

- **段の設定**（段ごと）: `cond`（4 ビット: bit0 = A、bit1 = B、bit2 = 番地一致、bit3 = ホスト指令。いずれかで成立）、
  `count`（成立が count 回で次の段へ。0 は 1 と同じ）、`within`（段に入ってから within 周期以内に次へ進めなければ
  段 0 に戻る。0 = 制限なし。段 0 は無視）。
- **段数** `stages`（1〜4）。最後の段を抜けたら SEQ を 1 周期出し、`fired` を立てて止まる（再び使うには
  enable を 0→1。単発の捕捉・停止と合わせるため）。発火の時刻（タイムベース）を記録する。
- 条件は同じ周期に複数あっても 1 回と数える。段を進めた周期の条件は次の段には数えない（同じ事象で 2 段進まない）。
- **CSR** `trigseq`（0x0A00）。xtrig の route の to_la / to_inject を 4 ビットに広げ、bit3 = SEQ。

## 3. 判断

| 判断 | 理由 | 誤っていた場合のコスト |
|---|---|---|
| パターンは捕捉の前段（la_front）と別に持つ | 捕捉のトリガは捕捉ごとに 1 回。シーケンサは捕捉と独立に事象を数える必要がある | 低（FF 約 70） |
| 4 段・2 パターン | 「A→B」「A→B→A」程度の実用例を満たし、資源（CLS 91%）に収まる。段数・パターン数は将来ジェネリックで増やせる | 低 |
| 単発（発火後は止まる） | 捕捉・停止は単発の動作。「N 回目」は段の count で表せる | 低 |
| 判定は毎 sys 周期（サンプルの間引きと無関係） | ロジアナの rate に依らず同じ時間分解能 | 低 |

## 4. 結果（2026-10-16）

- cocotb: 順序と制限時間、N 回目、番地一致・ホスト指令と 4 段（`tests/tb/trig_seq_tb.py`）。
- HIL: UART 送信の立ち下がり → 1 ms 以内に再び立ち下がりで深いバッファをトリガ。トリガは 2 回目の立ち下がりの
  1 サンプル（40 ns）後。間隔 10 ms の 2 バイトでは時間切れで成立しない（`test_xtrig_hw.py`）。MCP の
  `xtrig_set_sequence` / `xtrig_sequence_status`（`test_mcp_hw.py`）。
- 資源: LUT 約 +660（パターン比較、32 ビットの制限時間の比較、CSR 14 本）。Logic 80%、CLS 93%。
- 発火の記録は時刻だけ（単発なので回数は持たない）。
