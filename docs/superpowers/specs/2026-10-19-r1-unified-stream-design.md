# R1（F3b）: ロジアナの流し続けとイベントを 1 本の流れにする 設計

## 1. ゴールと完了条件

ロジアナの連続ストリーミング（M8 第 3 段）の間も、イベント記録（DAP・UART・SWO・補助・サンプラ）をデバイスの時刻のまま
同じ記録に取り込み続ける。今はどちらも深いバッファの読み出しの口（mem_reader → USB のストリーム EP）を使うので、
流している間は `events.read` 等が読めず、`recording.la_stream.start` の間はイベントが記録に入らない（F3 仕様 §4）。

| 完了条件 | 検証 |
|---|---|
| ストリームに、ロジアナの拍のかたまりとイベントのかたまりを、見出しの拍付きで交互に載せる | cocotb（la_deep_buffer、STREAM_EVENTS = true） |
| どちらも欠け・重複・順の入れ替わりが無い（受け手が止まっても）。イベントは指定した番号から始まる | cocotb |
| イベントの未読がリングの半分に達したら、ロジアナと同じく書き込みを止めて overrun（黙って欠けない） | cocotb |
| 止めると、止めた時点までに書いたイベントまでを出し切って終わる（その後のイベントは流さない） | cocotb |
| ホストが見出しを解いて波形とイベントに分け、記録（`recording.la_stream.start`）にイベントも入れる | pytest（偽の機器） |
| 機能のない構成（標準・JTAG 等）は今のまま（同じ回路・同じ形式） | 既存の cocotb・pytest |

## 2. 資源と構成の判断

標準（fprobe）は Logic 86%・CLS 97%・sys の余裕 0.13%（B22）。この機能は mem ドメイン（DDR3 側）に、見出しを挟む
128 ビットの選択（約 130 LUT）、イベントの読み位置・終わり・未読（19 ビット）、出すと決めた拍の総数（32 ビット）
などで 300 LUT 前後を足す。標準では CLS が満杯に近く、配置で sys のタイミングを崩すおそれが大きい。

- **generic `STREAM_EVENTS`（la_deep_buffer・fprobe_core）で切り替える**。false なら回路は今と同じ（generate で外す）。
- ケイパビリティ FEATURES の bit 6 `LA_STREAM_EVENTS` で申告する（無い古いデバイスは無い = 今の形式）。
  ホストは申告を見て、見出しを解くか、今の形式で受けるかを決める。
- **有効にする構成は fprobe_la**（ロジアナ向けの構成。サンプラ・故障注入を外してあり余裕がある）。長時間の
  「波形とイベントを同時に」はロジアナを主に使う場面なので、ロジアナの構成が持つのが自然。ホストは
  `DESIGN_FOR_LA_STREAM_EVENTS`（機能 → 構成）で選べる。標準に入れるのは、何かを外すか削減（B22 の A）の後。

## 3. ストリームの形式（STREAM_EVENTS の構成）

ストリームは「かたまり」の列。かたまり = 見出し 1 拍（16 バイト）+ 中身 count 拍。

| ビット | 内容 |
|---|---|
| [7:0] | 種類: 1 = ロジアナの拍（リングと同じ形式。RAW / RLE）、2 = イベント（1 件 = 1 拍、`decode_events` の形式） |
| [15:8] | 0 |
| [31:16] | count（1〜256） |
| [63:32] | 通し番号: ロジアナ = このかたまりの最初の拍の、ストリームの先頭からの番号（32 ビットで折り返す）。イベント = 最初のイベントのリングの位置（= events.written で数えた番号 mod capacity） |
| [127:64] | 印 `"FPRBSEG\0"`（0x0047455342525046。同期の確かめ） |

- `la_deep.stream_beats` は、この構成では「ストリームに出すと決めた拍の総数（見出し・イベントを含む。折り返す）」。
  ホストはこれと受け取った量の差だけを求める（今と同じ考え: 必ず届く量だけを要求する）。
- `la_deep.post_beats` は、この構成のストリームでは「最初に流すイベントの番号（events.written で数える。下位
  log2(capacity) ビットを使う）」。ストリームはトリガで止まらないので、ストリーム中の本来の意味は無い。ホストは
  記録の取り込み（collector）が読んだところの続きを渡し、つなぎ目で欠けも重複も出さない。
- 交互: 読み出し器が空くたびに、両方に未読があれば前回と反対の種類、片方だけならそちらを、最大 256 拍読む。
  イベントの帯域（最悪でも数 MB/s）はロジアナ（≤ 25 MB/s）より小さいので、どちらも飢えない。

## 4. 溢れと終わり

- ロジアナ: 今と同じ（未読 > リング − 256 拍で書き込みを止めて overrun）。
- イベント: 未読（書き位置 − 読み位置、リングの位置の差）が**リングの半分**に達したら、ロジアナの書き込みを止めて
  overrun を立て、以後イベントは流さない（ロジアナは出し切る）。半分で止めるので、読んでいる最中のイベントが
  上書きされることはない（判定は差の最上位ビット 1 本で済む）。ホストは overrun までに受け取った分が正しい。
- 終わり: run を 0 にすると書き込みを止め、その時点の書き位置までのイベントと、ロジアナの未読を出し切って終わる
  （`status.reading` が 0 に戻る）。その後のイベントは記録のリングに残り、`events.read` で読める（取り込みは続きから）。
- イベントの記録を流している間に始め直す（events.enable の 0→1）と、書き位置が 0 に戻るので読み位置も 0 に戻す
  （ホストは流している間に始め直さない。見出しの番号の飛びで分かる）。

## 5. 実装

- `la_mem_writer`: イベントの書き位置（ev_ptr）を出す（ポートを 1 つ足すだけ）。
- `la_deep_buffer`（generic STREAM_EVENTS）: ストリームの状態機械に、種類の選択・見出しの拍の送り出し（T_HDR）を
  足す。見出しは mem → sys の非同期 FIFO の手前で、読み出し器の出力と切り替える（読み出し器が止まっている間だけ
  送るので衝突しない）。読み出し器の領域はストリームでも種類で選ぶ。
- `fprobe_core`・トップ: generic を通す。`caps.Capabilities.la_stream_events`、設計の `fprobe_la` で有効。
- ホスト `fprobe.la`: `split_segments`（見出しを解く）、`LaStream` が申告を見て分け、`StreamChunk.events` に
  イベント（`DapEvent`）を渡す。`DeepAnalyzer.stream(events_from=…)`。
- ホスト `fprobe.recording_stream` / `probe_longrec`: 申告があれば、collector を止める前に読み切り、その続きの番号から
  流し、イベントを `add_events`（ポストされた読みの持ち越しも引き継ぐ）で記録へ入れ、終わったら collector に
  続きの番号と持ち越しを返す。申告が無ければ今のまま（流している間はイベントを取り込まない）。

## 6. 判断

| 判断 | 理由 | 誤っていた場合のコスト |
|---|---|---|
| 見出しの拍で種類を示す（中身に印を混ぜない） | ロジアナの拍は 128 ビットすべてが値なので、中身に印を置けない。16 バイト境界を保てる | 低 |
| generic で切り替え、fprobe_la で有効 | 標準は CLS 97%・sys の余裕 0.13% で、足すと配置が崩れるおそれ。B22 の方針（次に足すものは構成を分ける） | 低（generic を立てれば標準にも入る） |
| イベントの開始番号に post_beats を使う | ストリームでは使わないレジスタ。CSR を足すと読み出しの選択が増える（B22） | 低（CSR を足して移せる） |
| イベントの溢れはリングの半分で止める | 上書きと読みの競合を確実に避け、比較が 1 ビットで済む。リングは 52 万件（DAP の最悪で数秒分の遅れに耐える） | 低 |
| 止めた後のイベントは流さない（止めた時点の書き位置まで） | 書き込みの続くイベントを追うと終わらない。残りは記録のリングから読める | 低 |
