# PC 側 第 5 段: 画面の波形（タブ「波形」）設計

## 1. ゴールと完了条件

第 3 段の画面に「波形」タブを足し、ロジアナの捕捉（AI が取ったものも、人間が取ったものも）を見る。拡大・移動しても
滑らかで、深いバッファ（DDR3 128 MB、約 10 億サンプル）の捕捉でも同じ操作で見られる。

| 完了条件 | 検証 |
|---|---|
| 最後の捕捉（`la.capture` / `la.collect` / `la.deep.capture` / `la.deep.collect`、誰が取ったものでも）が波形で見える | 単体（Python・TS）+ 結合 |
| ホイールで拡大縮小（マウスの位置を中心）、ドラッグで移動、ダブルクリックで全体。トリガの位置に線 | 単体（TS: 座標の計算） |
| カーソルの位置の時刻（トリガ = 0）と各チャンネルの値が読める | 単体（TS） |
| 画面から捕捉できる（速度・トリガ前の量・トリガのチャンネルと向き・深いバッファ） | 結合 |
| 100 万変化点の捕捉の全体表示が 0.5 秒以内に返る | 単体（Python、時間を測る） |
| 実機: 画面から捕捉し、SWD の線の波形が見える | HIL（画像で確認し報告） |

非目標（後で）: DAP のイベント（`events.read`）の重ね描き、プロトコルの解読（SWD・UART）、カーソル 2 本の差、
複数の捕捉の比較、`la.stream` の VCD の表示（ファイルは PulseView で見る）。

## 2. 判断

| 判断 | 理由 | 誤っていた場合のコスト |
|---|---|---|
| デーモン（Probe）が最後の捕捉を変化点の形（`Transitions`）で持ち、画面には **画素ごとに縮めた波形** だけを返す | 画面の横幅は数千画素。全サンプルを送ると、どの描画の仕組みでも重い（Saleae Logic 2 等と同じ作り） | 低 |
| 縮め方: 1 画素 = サンプルの区間。チャンネルごとに `0`（ずっと 0）/ `1`（ずっと 1）/ `x`（区間内で変化）の 1 文字 | JSON で小さく（16 ch × 4000 画素 = 64 KB）、描画が単純 | 低（パルスの数を見せたくなったら数を足す） |
| チャンネルごとの変化点の表を捕捉のときに 1 回作り、表示のたびに二分探索で引く（画素ごとに 2 回）。numpy は使わない | 依存を増やさない。正確で、100 万変化点の全体表示も 0.1 秒ほど（表の作成は捕捉ごとに 1 秒ほど） | 低（遅ければ numpy に） |
| 描画は Canvas 2D | 縮めた波形は 1 画素 1 本の線なので十分速い。WebGL は要らない | 低 |
| 捕捉の取り直しは、記録（activity）に `la.*` の捕捉が流れたら波形を読み直す | AI が取った捕捉も人間が自動で見られる | 低 |

## 3. API に足すもの（版 1 のまま）

| 追加 | 内容 |
|---|---|
| `la.view`（read） | 引数 `start`（サンプル番号、既定 0）、`end`（既定 = 長さ）、`width`（1..8192、既定 1000）。結果 `{"capture": {id, length, sample_period_ns, trigger_index, channels, source}, "start", "end", "width", "levels": [チャンネルごとの文字列]}`。捕捉が無ければ誤り |
| `la.view` の `levels[ch][i]` | 画素 i = サンプル `[start + i·(end−start)/width, start + (i+1)·(end−start)/width)` の区間 |

`la.view` は API の仕様で `"record": false`（操作の記録に残さない。拡大・移動のたびの読みで AI の作業の記録が埋もれない）。
Probe は捕捉のたびに `Transitions` だけを持ち、変化点の表は最初の `la.view` でロックの外で作る（画面を使わない操作を遅くしない）。

`fprobe.la` に `Waveform`（`Transitions` を受けてチャンネルごとの変化点の表を作り、`view(start, end, width)` を返す）を足す。Probe は
捕捉のたびに `Waveform` を作り直し、`id` を 1 増やす。

## 4. 画面

```
┌ 作業 | デバッガ | 波形 ─────────────────────────────────────────────────────┐
│ 速度 [25 MHz▼] トリガ前 [1024] トリガ [ch3▼][立ち下がり▼] [ ]深い  [捕捉]      │
│ 捕捉 #3（claude、la.capture）8192 サンプル・40 ns/サンプル   カーソル +1.24 µs  │
├──────────┬──────────────────────────────────────────────────────────────┤
│          │ -10 µs        0         10 µs        20 µs                     │
│ ch0      │ ‾‾‾‾|____|‾‾‾‾‾‾‾‾|__|‾‾‾ ┊                                     │
│ ch1      │ ____|‾‾‾‾‾‾‾‾‾‾|________ ┊                                      │
│ SWDIO 駆動│ ▒▒▒▒▒▒                ┊                                      │
│ DAP 処理中│ ‾‾‾‾‾‾‾‾‾‾‾‾          ┊                                      │
└──────────┴──────────────────────────────────────────────────────────────┘
```

- チャンネル名: 0..7 = `ch0`..`ch7`（デバッグコネクタのピン）、8 = `SWDIO 駆動`、9 = `DAP 処理中`、他は `chN`。
- 拡大・移動のたびに、見えている区間を `la.view` で読み直す（連続した操作は 1 回にまとめる）。読み終わるまでは前の絵を
  伸縮して見せる。
- 拡大の限界は 1 サンプル = 32 画素。
- 捕捉のボタンは AI の作業中は確認を出す（第 3 段と同じ）。

## 5. 試験

- Python: `Waveform.view`（区間の値・変化・端・幅が長さより大きいとき・トリガ前後）、100 万変化点の速さ、
  `la.view` が捕捉の後に返る（Probe の捕捉を偽物で置き換えて）。
- TS 単体: 座標の計算（拡大の中心が動かない・限界・移動の端）、カーソルの時刻と値、捕捉が変わったら読み直す。
- 結合: 偽の機器（fake_daemon に `la_capture` の偽物: 決まった波形の `Transitions`）で、捕捉 → 表示の区間の読み出し。
- HIL: 実機で画面から捕捉し、画像で確認して報告に残す。
