# 画面に全 API を入れる（R23）

日付: 2026-10-22。利用者が方針と進め方を承認（2026-10-22）。利用者の方針（2026-10-22）:「全部入れるべき。AI ができて人ができない・AI の操作を人が見えない、を作らない」。

## 1. 目的

- AI（MCP）・スクリプトができる操作は、人も画面からできる。
- AI がした操作は、人が画面で見える。

## 2. 今の事実（調査、2026-10-22）

- API の定義は 1 か所に集まっています: `host/api/fprobe_api.json`。
  - メソッドは 305（read 91・control 214）。
  - 各メソッドに `summary`（日本語 1 行）と、引数の JSON Schema（`params`）があります。
  - MCP の道具は、この JSON から自動で作っています（`mcp_server.py` の `tool_function`）。
- 画面が呼ぶメソッドは 159 です。残りは 146（分類の下書き: docs/reports/2026-10-22-ui-api-coverage.md）。
- **AI の操作は、すでに人に見えています。**
  - デーモンは、すべての利用者の呼び出しを通知 `activity` で配り、`~/.fprobe/activity/` に残しています。
  - 画面の Activity パネルは、その呼び出しを利用者・役割（ai / human / script / hook）で絞り込めます。
  - 例外は `record: false` のメソッドです（画面の頻繁な読み取り）。これは記録しません。
- 引数ごとの説明（`description`）は 18 件しかありません。ほとんどの引数は型だけです。

## 3. 案（2 段）

### 段階 A: どの API も画面から呼べる「API」パネル（全 305）

- `fprobe_api.json` の定義から、フォームを自動で作ります。
  - 入力欄は引数の型で決めます: 整数・数・真偽・文字列・列挙・配列・null を許す、など。
  - 整数は 16 進数でも入れられるようにします。
- メソッドは、名前の前半（target・la・rtos …）の木と、検索で選びます。表示は `summary` です。
- 呼ぶと、結果を JSON の木で見せます。
  - 呼び出しは利用者 human として、Activity と記録に残ります（今の仕組みのまま）。
- control（書き込み・実行）のメソッドは、呼ぶ前に引数を見せて確かめます。
- Activity パネルの行から「同じ呼び出しを API パネルで開く」ができるようにします。AI がしたことを、人がそのまま再現できます。
- 新しいメソッドを足すと、自動でここに出ます。画面の作業は要りません。

これで「AI ができて人ができない」は、段階 A だけで無くなります。

### 段階 B: よく使うものに専用の画面（B の上位から）

分類の下書きの B の上位 10 は、次のとおりです。

1. 接続の失敗の理由（target.diagnose）
2. 故障の状態の保存（snapshot）
3. 捕捉の保存（la.export）
4. 保護の解除（option bytes・unlock）
5. 命令の履歴（ETM）
6. ヒープ
7. サイクル数
8. スタックのあふれ
9. ログ（defmt / trice）
10. DAP の直接の読み書き

これらは、関係するパネル（接続ダイアログ・Fault・LogicAnalyzer・Flash・Threads・Terminal 等）に入れます。
1 つずつ別の計画にします（どれも小さい）。

### 合わせて直すこと

- 引数ごとの説明を `fprobe_api.json` に足します。これは段階 A のフォームの説明になり、MCP の道具の説明にも効きます。
- 説明は日本語と英語の両方が要ります。画面の言語の切り替え（i18n.ts）は、`summary` とつながっていないためです。
- 置き場所は `fprobe_api.json` に `summary_en` 等で持つ案です（利用者の判断）。

## 4. 決めたこと（2026-10-22）

- 2 段で進める（利用者）。段階 A を先に作る。
- 段階 A の範囲は、MCP の道具と同じにする（Claude の判断）。
  - 外すのは session.*（6。つなぎ方の手続き）と binary の timeline.tiles（1。画面の時間軸の専用の経路）です。
  - これで「AI ができること」と「人が API パネルでできること」が一致します。
- 確かめ（利用者）:
  - read は、確かめずに呼ぶ。
  - control は、呼ぶ前に引数を見せて確かめる。
  - 取り返しのつかない操作は、赤い確かめにする。
- 「取り返しのつかない操作」は、名前からの推測ではなく fprobe_api.json の印 `irreversible: true` で決める（Claude の判断。CLAUDE.md の「ヒューリスティックを入れない」）。
  - 対象は、Flash・オプションバイトの書き込み・消去・保護の解除です。
  - 使い方によって元に戻せない 4 つにも付ける（利用者、2026-10-22）: Flash の速度の測定（書き込み先を渡すと消して書く）・DAP の AP への直接の書き込み（nRF の CTRL-AP の全消去）・Flash 上のブレークポイント・Flash を読んで PC のファイルに保存（上書き）。
  - 印は MCP の道具の説明にも出せます。
- 引数の欄は、引数の型（JSON Schema）から作る（Claude の判断）。
  - 整数・数・真偽・文字列・列挙と、それぞれの null を許す形は専用の欄にする。整数は 16 進数（0x…）でも入れられる。
  - 配列・オブジェクト・そのほかは JSON の文字列で入れる。
  - 空の欄は送らない（既定の値はデーモンが決める）。
- 説明の英語（summary_en 等）は段階 A に入れない（Claude の判断）。英語の画面でも summary は日本語のまま出す。

## 5. 以前の「利用者に決めてもらうこと」（済）

1. この 2 段でよいか（まず段階 A で「全部入る」を満たし、段階 B は効き目の大きい順に）。
2. 段階 A の control のメソッドの扱い。
   - 案は「呼ぶ前に引数を見せて確かめる」です。
   - 危ない操作（Flash の消去・option bytes・unlock 等）は、もう一段確かめる案です。
3. 説明の英語をどこに持つか。

## 6. やらないこと

- 画面だけの別の操作経路は作りません。画面も AI と同じ API を呼びます。
- API パネルに、メソッドごとの手書きの画面は作りません。それは段階 B でします。
