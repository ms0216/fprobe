## 2. 構成

```
（ボード固有）primer20k_fprobe_top
   メモリ用 rPLL（27 → 398.25 MHz）─ primer20k_ddr3 ─ DDR3MI（Gowin の DDR3 IP、暗号化ネットリスト）─ DDR3 ピン
                                         │ mem_port（mem_clk = 99.56 MHz のドメイン）
（ボード非依存）fprobe_core（MEM_ADDR_BITS = 23。0 なら外部メモリ無し）
   csr_mem ─ mem_test_sys（sys ⇄ mem の受け渡し）─ mem_test（mem ドメイン）
```

- **mem_port**（ボード非依存のメモリ I/F）: 1 コマンド = 1 拍（16 バイト）。`cmd_valid/ready`・`cmd_write`・`cmd_addr`
  （拍の番号）・`cmd_data`（書き込みはコマンドと同時）。読み出しは発行順に `rd_valid` + `rd_data`（受け側は止められない）。
  PSRAM / HyperRAM / BSRAM の実装も同じ I/F で作る（小さいボード向け）。
- **primer20k_ddr3**: IP の番地 {rank, bank, row(14), column(10)} へ、拍の番号 23 ビットを {0, bank, 0 & row(13),
  column 上位 7 ビット & 000} と並べる。IP のリセット出力（入力クロック側）は mem_clk に同期化して使う。
- **mem_test**: start で base から count 拍に番地依存のパターンを書き、読み戻して比べる。誤り数・最初の誤り・
  書き込み / 読み出しの周期数（帯域）。番地線の断線・折り返しも誤りとして現れる（容量の確認に使った）。
- **mem_test_sys**: 引数・結果を cdc_value で受け渡す。start から新しい結果が届くまで busy（前回の done を見せない）。
  診断用に mem 側のリセット中・クロックの動作（計数の 1 ビット）も出す。
- CSR `mem`（docs/registers.md）、ケイパビリティ `MEM_BYTES`、ホスト `fprobe.memory.Memory`。
- （2026-10-16 追記）メモリ試験回路は基板立ち上げ用の構成 `memtest` だけが持つ（ケイパビリティ `MEM_TEST` = 12。VHDL の定数と同じ定義から生成）。製品構成 `fprobe` は回路の空きを機能に回す。
- ビルド: `GowinIp`（ベンダー IP の記述）。生成（create_ipc / set_property / generate_target、設定が同じなら省略）か、
  Gowin のインストールにある生成済みネットリストの取り込み（prebuilt）。

## 3. 判断

| 判断 | 理由 | 誤っていた場合のコスト |
|---|---|---|
| コントローラは Gowin の DDR3 IP（LiteDRAM・自作は後で検討） | ツールに同梱で、この基板での実績がある。mem_port の裏に隠すので差し替えは局所的 | 低 |
| IP は Gowin IDE 同梱の Sipeed の参考デザイン（Cam2HDMI）の生成済みネットリスト（V1.9.8 で生成）を使う | 現行の V1.9.11 の生成器で同じ設定から作った IP（`ddr3_1_4code_hs`）は較正が終わらなかった。同梱品は較正・全容量の試験とも通る | 中: Gowin を更新して同梱品が変わると影響。原因が分かれば生成に戻す |
| 容量は 128 MB（1 Gb x16、行 13 ビット） | 256 MB として試すと 16 MB ごとに折り返した（行の 14 ビット目が無い） | 低 |
| mem ドメインは sys と非同期として扱い、メモリクロック ⇄ ユーザー側クロックの経路は IP に任せる | Gowin の参考デザインもメモリクロックだけを制約している。こちらの回路はすべて同期化回路で受け渡す | 低 |
| sys と入力クロック（27 MHz）も非同期として扱う | 間で値を直接受け渡す回路が無い。IP のリセット出力の同期化で誤った違反が出ていた | 低 |

## 4. 併せて行った資源の削減（ファブリックが 96% まで埋まり、タイミングがばらついたため）

- jtag_phy: 64 ビット列を可変位置で組み立てる作り → 区間ごとにビットを数えて出す作り（約 2,000 LUT 減）
- swd_phy: シーケンス読み取り結果の可変量シフト → ビット番号の位置へ直接書く
- 結果: 論理 84% → 72%、sys Fmax 113 MHz、mem 100.3 MHz

## 5. 第 2 段: ロジアナの深いバッファと USB での読み出し

完了条件: 16 ch × 100 MS/s を 128 MB に記録し（RAW で 64 M サンプル = 0.67 秒、変化点圧縮では信号次第でそれ以上）、
トリガ前後を USB のストリーム EP で読み出して VCD にできる（HIL: SWD 通信を DDR3 に捕捉）。

```
（sys）la_front（同期化・サンプル間隔・トリガ判定。la_capture と共用）→ la_encoder（RAW / 変化点 → 128 ビットの拍）
   → 非同期 FIFO → （mem）la_mem_writer（DDR3 をリングとして書く。トリガ後 post_beats 拍で止める）
（mem）mem_reader（拍の範囲を読む）→ 非同期 FIFO → （sys）拍 → バイト → USB ストリーム EP
mem_port は mem_test / la_mem_writer / mem_reader が排他で使う（CSR の状態で決まる）
```

- **符号化**（拍 = 16 バイト）:
  - RAW: 1 拍 = 8 サンプル（16 ビット × 8、下位から時間順）。帯域 200 MB/s（100 MS/s）。
  - 変化点（RLE）: 1 拍 = 4 レコード（32 ビット = 値 16 ビット + 繰り返し 16 ビット。値が count + 1 サンプル続いた）。
    値が変わるか 65536 サンプルでレコードを閉じる。トリガのサンプルで必ず新しいレコードを始める（トリガ = レコードの頭）。
    最悪（毎サンプル変化）400 MB/s。DDR3 の書き込み 504 MB/s 以内だが、詰まったら**捨てて OVERRUN を申告**する。
- **トリガ**: la_front の判定（値一致・エッジ・外部トリガ）。トリガの拍の位置・拍の中の番号・タイムベースの時刻を記録。
  トリガ前に書けていた量（最大 容量 − post_beats）をホストが知れるよう、書いた拍の総数（容量で飽和）も出す。
- **取りこぼしを黙らない**: 符号器から FIFO に入れられなかった拍があれば OVERRUN（状態ビット）。
- 読み出しは `mem_reader`: (開始の拍, 拍数) を受けて読み、mem 側の受け皿（同期 FIFO）の空きを見ながらコマンドを出す
  （読み出しの結果は止められないため）。
- 第 3 段（後）: DDR3 を大きな FIFO として使う連続ストリーミング（書きと読みを同時に）。

### 第 2 段の結果（2026-10-16）

- HIL: pyOCD の SWD 通信を 100 MS/s で捕捉。RAW 176,008 サンプル（22,001 拍）、変化点圧縮では同じ拍数で 3,300 万サンプル
  （0.33 秒、約 380 倍）。トリガ位置（プローブが SWDIO を離した瞬間）が両方で一致。
- 読み出し 40 MB/s（USB HS のバルクの実効、復号込み）。128 MB 全体で約 3.2 秒。
- ホスト: 変化点のまま扱う `Transitions`（長い RLE を毎サンプルに展開しない）、VCD も変化点から書く。MCP に la_deep_*。
- タイミング: ボード固有ラッパの入口（mem_port → IP）にレジスタスライス。mem の余裕は 0.4%（99.98 / 99.56 MHz）と薄い。
- 資源: 論理 78%、CLS 92%、BSRAM 94%（128 ビット幅の FIFO が幅の分だけ BSRAM を使う）。
