# linux.halt の設定の保存・読み込み（`linux.halt.profile.*`）— 設計

## 目的
open（約 12 個）と attach（約 12 個）の引数を毎回書くのは手間で、書き違えも起きる。設定をファイルに保存して読み込めるようにする。
人（画面）と AI（MCP）が同じ API で同じに使える。

## 決めたこと
- `save(path)` は開いている口の事実（`HaltOptions.as_dict()`、attach 中なら `debug.status` の options から pid を除く）を書く。
- `load(path)` は読んで返すだけ（副作用なし）。open・attach は既存の API に返った値を渡す。理由: (1) 「黙って既定の値を使う」形を作らない、
  (2) 実行した引数がそのまま操作の記録に残る、(3) 画面と MCP が同じ。
- **pid は保存しない**（実行のたびに変わる）。プロセス名から引く道は作らない（同名が複数のときの選び方がヒューリスティックになる）。
  pid は `linux.halt.processes` で見て、使う側が選ぶ。
- offsets は SHA-256 だけ保存し、読み込みで「今のファイルと同じか」を事実として返す（`offsets_matches`。比べるだけで判定・停止はしない）。
- 形式は版つき（`format` / `version`）。違えば読み込みを断る。
- 画面は、パスの欄と「保存」「読み込み」の 2 つのボタン（Linux パネルの設定の中）。読み込みは欄に入れるだけ。

## 範囲外
- デーモンの起動の引数・SSH の設定・ブレークポイントの保存（別の仕様）。
