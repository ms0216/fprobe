# M3: コントロールプレーン（CSR・ケイパビリティ・タイムベース）設計

- 日付: 2026-10-15
- 親: `2026-10-15-fprobe-architecture-design.md` §4.1（共通基盤）、§3.2（CONTROL ch）、§9（ホスト）

## 1. ゴールと完了条件

PC から CONTROL チャンネル（USB では EP1）経由で **32 ビットレジスタ（CSR）を読み書き**でき、デバイスが申告する
**ケイパビリティ**を取得できるようにする。以後の全機能（SWD、ロジアナ、クロストリガ…）はこの CSR 空間に
レジスタを足して設定・観測する。

| 完了条件 | 測り方 |
|---|---|
| ホストライブラリ `fprobe` から CSR の読み書き（単発・連続）ができ、不正要求には仕様どおりのエラーが返る | シミュレーション（ホストライブラリの符号化をそのまま使う）+ HIL |
| ケイパビリティ（ボード名・プロトコル版・クロック・機能一覧）を取得・解析できる | 同上 |
| タイムベース（64 ビット、10 ns）が読め、単調増加し、実時間と整合する | HIL（ホストの経過時間と比較、±1%） |
| レジスタ定義・ケイパビリティは Python の単一定義から VHDL・ホスト Python・Markdown を生成し、一致を pytest で検査 | pytest |
| 全 entity に cocotb テスト。合成でタイミング達成 | pytest / GowinBuilder |

## 2. 構成

```
 usb ドメイン                    │ sys ドメイン (100 MHz)
                                 │
 usb_device EP1 OUT ─ async_fifo ┼→ fprobe_core ┬ control_plane ─(CSR バス)─ csr_decoder ┬ csr_bank_system（生成）
 usb_device EP1 IN  ← async_fifo ┼←             │                                       ├ csr_bank_timebase（生成）← timebase
                                 │              │                                       └ caps_rom（生成内容）
```

- `fprobe_core`（ボード非依存）が sys ドメインのコア全体を束ね、CONTROL チャンネルのストリーム（データ 8 + last）だけを外に出す。
  ボードのトップはクロック・リセット・USB・FIFO を用意して `fprobe_core` をつなぐだけにする（移植時もここは変わらない）。
- 新しい製品デザイン `fprobe`（トップ `primer20k_fprobe_top`）を追加する。M2 の `usbtest` は USB 単体の試験用に残す。
  CDC（UART）とストリーム EP は M6/M7 で機能をつなぐまで未接続（OUT は受け捨て、IN は送るもの無し）。

## 3. CONTROL プロトコル（ch 0）

1 メッセージ = 1 USB パケット（M2 の取り決め）。リトルエンディアン。ホストは要求を MPS（HS 512 / FS 64）以内に収める。

**要求**（ヘッダ 8 バイト）

| バイト | 内容 |
|---|---|
| 0 | op: `0x01` READ / `0x02` WRITE / `0x03` EXCHANGE（プロトコル 2、U42 で追加） |
| 1 | tag（ホストが付け、応答にそのまま返る） |
| 2–3 | count: 32 ビットワード数（1 以上） |
| 4–7 | addr: バイトアドレス（4 の倍数）。ワードごとに +4 |
| 8– | WRITE のデータ（count × 4 バイト） |

**応答**（READ のデータの後に、末尾 4 バイトの状態）

| バイト | 内容 |
|---|---|
| 0 – 4·done−1 | READ のデータ（done × 4 バイト。WRITE では無し） |
| 末尾 0 | tag |
| 末尾 1 | status: `0` OK / `1` BAD_OP / `2` BAD_LENGTH / `3` BUS_ERROR |
| 末尾 2–3 | done: 実行したワード数 |

- 状態を末尾に置くのは、ゲートウェアが読んだワードをそのまま流せるようにするため（先頭に置くと、途中のバスエラーに
  備えて全データをバッファする必要がある）。ホストは受信長から構造を復元する（データ長 = 受信長 − 4）。
- BAD_OP: op が未知。何も実行しない。
- BAD_LENGTH: count = 0、addr が 4 の倍数でない、READ の要求が 8 バイトでない、WRITE のデータが count × 4 バイトでない。
  検出した時点で止め、done はそれまでに実行したワード数（READ と、count / addr の不正では 0。
  WRITE のデータ不足・余りは、それまでに届いた完全なワードは書いてある）。
- BUS_ERROR: 未割り当てアドレス等でバスがエラーを返した。そのワードで止め、done はそれまでの数。
- 応答は要求ごとに必ず 1 つ返す（ホストは tag で対応を確認する）。READ の応答は複数パケットになりうる（短パケットで終端）。
  エラーで止めた要求の残りのバイトは読み捨てる。
- 2 バイト未満の要求でも応答する（tag は無ければ 0）。
- EXCHANGE（プロトコル 2）: 形は WRITE と同じ。データの各ワードを addr に書き、続けて同じ addr を読み、読んだワードを
  応答のデータに流す（addr は進めない。応答は READ と同じ形で done ワード）。長さの検査は WRITE と同じ。
  「書いて応答を読む」レジスタ（gpio の io = 書くと出力、読むと端子）を 1 要求で何度も使うためのもの
  （ビットバングの SPI。docs/superpowers/specs/2026-10-19-u42-spi-flash-design.md）。

## 4. CSR バス

sys ドメイン、単一マスタ（control_plane）。要求を `ack` まで保持する 2 相ハンドシェイク:

| 信号 | 向き | 意味 |
|---|---|---|
| `bus_req` | M→S | 要求あり（`bus_ack` まで保持） |
| `bus_we` | M→S | 1 = 書き込み |
| `bus_addr` | M→S | ワードアドレス（バイトアドレス / 4、30 ビット） |
| `bus_wdata` | M→S | 書き込みデータ |
| `bus_ack` | S→M | 完了（1 周期パルス） |
| `bus_err` | S→M | `ack` と同時。未割り当て等 |
| `bus_rdata` | S→M | `ack` と同時に有効 |

`csr_decoder` は窓（ベースとサイズ、ジェネリック）ごとに要求を振り分け、どの窓にも当たらなければ自分で `ack + err` を返す。
読み出しに数周期かかるスレーブ（BSRAM の ROM、将来の他ドメイン越しのレジスタ）もそのまま扱える。

## 5. レジスタ定義と生成（単一の真実の源）

`fprobe_gw/csr/` に定義用の小さな DSL と生成器を置く。定義はブロック（窓）とレジスタとフィールド:

- フィールドの種類: `RW`（ゲートウェアへ出力）、`RO`（ゲートウェアから入力）、`CONST`（定数）。
- レジスタの付加動作: `read_strobe`（読まれた周期にパルスを出す。例: 64 ビット値のスナップショット）。
  書き込みパルス等は使う機能が出てきた時点で足す。
- 窓内で未定義のワードへのアクセスはバスエラー。RO / CONST への書き込みは無視する（エラーにしない）。
- 生成物（コミットし、一致を pytest で検査。`python -m fprobe_gw gen` で再生成）:
  1. `rtl/core/generated/csr_<block>.vhd`: ブロックごとのレジスタバンク entity（CSR バスのスレーブ。フィールドごとのポート）
  2. `rtl/core/generated/csr_map_pkg.vhd`: 窓のベース・サイズ、プロトコル定数（op・status）
  3. `host/fprobe/generated.py`: レジスタ・フィールド・プロトコル定数・ケイパビリティ種別
  4. `docs/registers.md`: レジスタ表

M3 のアドレスマップ:

| 窓 | ベース | サイズ | 内容 |
|---|---|---|---|
| `system` | `0x0000_0000` | 0x40 | `MAGIC`（CONST `"FPRB"` = 0x42525046）、`VERSION`（CONST、プロトコル版）、`SCRATCH`（RW、疎通試験） |
| `timebase` | `0x0000_0100` | 0x40 | `TIME_LO`（RO、読むと上位を `TIME_HI` に保持）、`TIME_HI`（RO、保持した上位） |
| `caps` | `0x0000_1000` | 0x1000 | ケイパビリティ ROM（読み出し専用、範囲外は 0） |

## 6. ケイパビリティ

デザインごとに Python で宣言し、TLV 列にして ROM の初期値（VHDL パッケージの定数）として生成する。

- 先頭: `"FCAP"`（0x50414346）、総バイト数（u32）。
- 以降の項目: `type (u16), length (u16), value`（4 バイト境界まで 0 詰め）。type = 0 で終端。
- M3 の種類: `PROTOCOL_VERSION`(u32)、`BOARD`(文字列)、`DESIGN`(文字列)、`SYS_CLOCK_HZ`(u32)、`TIMEBASE_HZ`(u32)、
  `HOST_LINK`(u32: 1 = USB HS/ULPI)、`CHANNELS`(u32 ビットマップ: §3.2 の ch 番号)。
- 以後の追加: `LA_CHANNELS`(8)・`LA_DEPTH`(9、0 = 内蔵バッファ無し)・`LA_SAMPLE_HZ`(10)、`MEM_BYTES`(11)、
  `MEM_TEST`(12、u32 = 1: メモリ試験回路あり)。回路の有無を決める VHDL 定数も同じ宣言から生成する。
- 未知の種類はホストが読み飛ばす（新しいゲートウェアと古いホストが共存できる）。

## 7. タイムベース

sys クロックで数える 64 ビットのフリーラン（Primer では 100.2857 MHz → 1 カウント ≈ 9.97 ns。正確な周波数は
ケイパビリティの `TIMEBASE_HZ` で申告し、ホストが換算する）。他ドメインへの配布は使う機能（M7/M9）で追加する。

## 8. ホスト（`host/fprobe`）

- `transport`: pyusb + libusb-package。VID/PID 1209:0001 とインターフェース文字列 `fprobe control` で探す（シリアル指定可）。
- `control`: §3 の符号化・復号、MPS に合わせた分割、tag 照合、エラーの例外化（`ControlError`）。
- `caps`: TLV の解析。
- `device`: `Device.open()`、`read(addr, n)`、`write(addr, words)`、`capabilities()`、`time()`。
- `generated`: §5 の生成物。
- 単体テスト（偽トランスポート）と、ゲートウェアのシミュレーション・HIL からも同じ符号化を使う。

## 9. 判断（ユーザー確認なしで決めたもの）

| 判断 | 理由 | 誤っていた場合のコスト |
|---|---|---|
| Stream はレコード型にせず、`<prefix>_valid/ready/data(/last)` の個別ポートのまま | VHDL-2008 では向きの混在したレコードをポートにできない（VHDL-2019 のモードビューが要る）。CLAUDE.md の規約と既存コードに一致 | 低（後でラッパを足せる） |
| 応答の状態を末尾に置き、長さ不正は検出時点で止める（done で実行済みを申告） | 先頭に状態を置く・長さ不正で何も実行しない、とするとゲートウェアに最大数 KB のバッファが要る。ホストは done で実行範囲を正確に知れる | 低 |
| 要求は 1 USB パケットに収める（分割はホスト） | M2 の「パケット = メッセージ」をそのまま使え、ゲートウェアが単純 | 低。WRITE は HS で 1 要求 126 ワードまで |
| ケイパビリティは CSR 空間の ROM として読む（専用要求を作らない） | 読み出しの仕組みが 1 つで済む | なし |
| ビルド ID（git ハッシュ等）は申告しない | 生成物がコミットごとに変わり、一致検査と相性が悪い | 低。必要になればビルド時生成で追加 |
| 再生成コマンドを `gen-usb` から `gen`（全生成物）に一本化 | 生成物が増えるため | なし |
