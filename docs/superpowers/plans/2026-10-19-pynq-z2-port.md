# PYNQ-Z2 への移植（P0〜P2）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PC 側を変えずに、PYNQ-Z2 の上の fprobe（BRAM のロジアナ）を LAN 越しに使え、XIAO を Primer と同じようにデバッグできるようにする。

**Architecture:** PL は既存のコア（無変更）＋新しい `zynq_frame_link`（AXI4-Lite のスレーブ ↔ 既存の `frame_mux` の受け渡しの RAM）。PS の Linux で C の中継 `fprobe-relay` が UDP 63920 のデータグラムとフレームを 1 対 1 で受け渡す（Ethernet 版と同じ線上の形式）。道具（`fprobe_gw`）に Vivado を足し、ボードが使う道具を持つ。

**Tech Stack:** VHDL-2008（GHDL 6 + cocotb 2 で検証、Vivado 2025.2 で合成）、Python 3.13（fprobe_gw）、C（中継。PC での試験は zig cc で共有ライブラリにして ctypes から、PYNQ では gcc）、PYNQ の Linux（SSH・fpgautil）。

**Spec:** docs/superpowers/specs/2026-10-19-pynq-z2-port-design.md（§10 の「決めたこと」も読む）

## Global Constraints

- コア（`gateware/rtl/core` 等のボード非依存の RTL）に PYNQ のための分岐を入れない。入れてよいのは汎用の改良だけで、Primer の試験も通す（仕様 §2 ゴール 3）。
- PC 側（`host/fprobe`）に PYNQ のための分岐を入れない。PC は `--eth <IP>` で使い、違いはケイパビリティの申告だけ。
- ベンダーの暗号化 IP を使わない（PS7 のブロック設計は例外）。Xilinx のプリミティブ（MMCM・BUFG・IOBUF）は `gateware/rtl/boards/pynq_z2/` の包みの中だけ。
- 線上の形式は Ethernet 版と同じ: UDP ポート 63920、`ch(1) | seq(1) | payload(0..512)`、PL → PC の `seq` は全チャンネル共通の 8 ビットの通し番号、宛先は最後に正しいデータグラムを送ってきた送り主。
- M_AXI_GP0 の ACLK は sys（MMCM の 100 MHz）。FCLK は使わない。sys は 125 MHz（H16）から MMCM で作る。
- PYNQ の PL の書き込みはふだん Linux 経由（SSH と fpgautil）。JTAG（Vivado の hw_server）は復旧・ILA の調査だけで、シリアル `1234-TUL` で口を選び、IDCODE が Zynq-7020 であることを照合してから書く。
- VHDL の規約は CLAUDE.md のとおり（VHDL-2008、ASCII の文字列、numeric_std、同期のアクティブハイの `rst`、`S_` の状態名、すべての信号を明示的に駆動、すべての entity に cocotb の試験）。
- Vivado の場所: `C:\AMDDesignTools\2025.2\Vivado\bin\`（環境変数 `FPROBE_VIVADO_HOME` で変えられる）。デバイス `xc7z020clg400-1`。
- 配線（仕様 §8）: PMOD JA1 = SWCLK（ch0）、JA2 = TDI（ch1）、JA3 = nRESET（ch2）、JA4 = SWDIO（ch3）、JA7 = 予備（ch4）、JA8 = UART RX（ch5）、JA9 = SWO（ch6）、JA10 = UART TX（ch7）。PMOD JB = 専用の入力 ch10〜15。
- 補助（aux）は入れない（`aux=False`）。

## Review Focus

1. AXI4-Lite のどの番地・どの状態の読み書きにも必ず応答する（応答しないと ARM が固まり、JTAG か電源の入れ直しが要る）。→ Task 4 の試験 `test_every_address_answers`。
2. 中継が動いたまま PL が書き直される・PL が未構成のとき、中継が PL の窓を読み続けて固まらない（設計の版の語を確かめてから受け渡しを始め、読めなければ止めて報告）。→ Task 5 の試験 `test_relay_refuses_without_the_design`。
3. 長さ 0 のデータグラム・513 バイト以上のデータグラム・未知の ch は、捨てて数え、他のフレームを壊さない。→ Task 5 の試験 `test_bad_datagrams_are_dropped_and_counted`。
4. PC → PL の FIFO が詰まったら中継が待つ（欠けない）。PL → PC の送りの FIFO が溢れたら数えて報告する（黙って欠けない）。→ Task 4 `test_rx_backpressure`、Task 5 `test_full_rx_makes_the_relay_wait`。
5. PC が送り主を替えたら（別の PC・ポート）、以後は新しい送り主へ送る。→ Task 5 `test_peer_follows_the_last_sender`。

### Task 4: `zynq_frame_link`（AXI4-Lite ↔ frame_mux）

**Files:**
- Create: `gateware/rtl/hostlink/zynq_frame_link.vhd`

**Interfaces:**
- Consumes: `frame_mux` の受け渡しの口（`rx_we`・`rx_waddr`・`rx_wdata`・`rx_commit`・`rx_len`・`rx_busy`・`tx_valid`・`tx_len`・`tx_raddr`・`tx_rdata`・`tx_done`。仕様は `frame_mux.vhd` の頭の説明）
- Produces: entity `zynq_frame_link`（generic `MAX_PAYLOAD := 512`、`RAM_BITS := 10`）。AXI4-Lite のスレーブ（`s_axi_*`、32 ビット、番地 12 ビット）。レジスタ（番地はバイト）:

| 番地 | 名前 | 読み | 書き |
|---|---|---|---|
| 0x000 | ID | 0x46504C4B（"FPLK"）| — |
| 0x004 | VERSION | 1 | — |
| 0x008 | RX_STATUS | bit0 = busy（frame_mux が受け取り中で書けない） | — |
| 0x00C | RX_COMMIT | — | [9:0] = 長さ（ch を含むバイト数）。書くと 1 フレームを渡す |
| 0x010 | TX_HEAD | [9:0] = 長さ（ch を含む。無ければ 0） | — |
| 0x014 | TX_DONE | — | 何を書いても、今の送りのフレームを読み終えた |
| 0x018 | DROPS | 受け取りの捨てた数（busy の間の commit・長さが範囲外） | — |
| 0x400〜0x7FF | RX_BUF | — | 4 バイトずつ（リトルエンディアン）。番地 0 = ch、1〜 = payload |
| 0x800〜0xBFF | TX_BUF | 4 バイトずつ | — |
| その他 | — | 0 を返す（SLVERR は返さない） | 無視して OKAY |
