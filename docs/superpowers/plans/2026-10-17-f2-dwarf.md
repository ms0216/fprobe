# F2（DWARF）実装計画

仕様: [2026-10-17-f2-dwarf-design.md](../specs/2026-10-17-f2-dwarf-design.md)。各段は TDD（失敗する試験 → 実装 → 通る）で、段ごとに commit する。
試験は `PYTHONPATH=host .venv/Scripts/python -m pytest host -q -p no:cacheprovider`（作業場所の `host` を先に読むため）。

1. **試験用ファーム** `host/firmware/dwarf_demo/`（C・link.ld・build.py、3 つの ELF）。
2. **読み手** `access.py`: `TargetAccess`、レジスタ番号 ⇄ 名前、`ImageAccess`（疎なメモリ・書き込み）。
3. **型** `typesys.py`: DIE → 型、`strip`、`type_name`、ビットフィールドの位置。試験: Sensor の各メンバー・多次元配列・修飾子・列挙。
4. **値** `values.py`: decode / encode。試験: 合成した型 + バイト列、ELF の初期値（sensors・matrix・ramp・greeting・big）。
5. **位置式** `location.py`: スタック機械・Place・読み出し。試験: 合成した式（算術・bra・piece・stack_value・convert）。
6. **デバッグ情報** `info.py`: 関数・スコープ・変数・ロケーションリスト（PC で選ぶ）・型の名前。試験: O0 / O1 / DWARF 4。
7. **巻き戻し** `unwind.py`: CFI・例外のフレーム。試験: 逆アセンブルでなぞった偽のスタック（O0 の再帰、O1、例外の 4 通り）。
8. **C の式** `cexpr.py`: 字句・構文・評価。試験: `head->samples[1][2]`、`*p`、`&v`、キャスト、`walk::visits`、エラー。
9. **窓口** `inspector.py`: backtrace(variables) / frame_variables / read / write。
10. **Debugger への組み込み**: `PyocdAccess`、CFI の backtrace、`evaluate` 等。既存の試験が通ること。
