# 人間用の画面 v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** fprobe-daemon が配るブラウザの画面から、AI の作業を見て、一時停止・交代し、プローブとターゲットの状態を見る。

**Architecture:** デーモン（Starlette）に記録の読み出し・利用者の通知・ターゲットの見張り・静的配信を足す。画面は
`host/ui/` の Vite + Svelte 5 + TypeScript。API との境界（DaemonConnection）と画面の状態（AppState）は Svelte に依らない
素の TS で、Svelte の store の約束（`subscribe`）だけを満たす。部品は表示と操作の受け渡しだけ。

**Tech Stack:** Python 3.13 / Starlette 1.8 / uvicorn、Node.js 24 / Vite / Svelte 5 / TypeScript / Vitest / svelte-check。

**Spec:** docs/superpowers/specs/2026-10-17-host-gui-v1-design.md

## Global Constraints

- API の版は 1 のまま（足すだけ）。仕様の正は `host/api/fprobe_api.json`、変えたら `python -m fprobe.api gen`。
- 画面は `hello` で `role: "human"`、名前 `gui`。トークンは URL の `#token=...`。
- `host/ui/dist/` と `host/ui/node_modules/` は git に入れない。
- 見張りの読みは記録しない。一時停止中も動く。
- コメント・文書・画面の文言は日本語。
- 実機（HIL）・ビルド・書き込みは Primer の安全な書き込みツールだけ。PYNQ-Z2・Nano 9K・ST-LINK には触れない。

## Review Focus

1. デーモンの再起動で記録の番号が 1 に戻る → 画面は古い行と混ぜず読み直す（state の試験）。
2. 切断中に押したボタン → 待たずに誤りを示す（api の試験: 未接続の call は即 reject）。
3. 見張りの target_status が「未接続」以外の誤り（USB が抜けた等）→ デーモンは落ちず、送らない（Python の試験）。
4. 同じ記録が一覧（list）と通知（activity）の両方から来る → 1 行だけ（state の試験）。
5. dist が無いデーモン → `/` はビルド手順の 1 枚、`/api` は動く（Python の試験）。

### Task 2: 画面の土台と API の境界（DaemonConnection）

**Files:**
- Create: `host/ui/package.json`, `vite.config.ts`, `tsconfig.json`, `svelte.config.js`, `index.html`, `src/main.ts`,
  `src/lib/api.ts`, `tests/api.test.ts`, `.gitignore`（`node_modules/`, `dist/`）

**Interfaces:**
- Produces:
```ts
export type LinkState = "connecting" | "open" | "closed";
export class RpcError extends Error { code: number }
export class DaemonConnection {
  constructor(url: string, opts: { name: string; role: "human" | "ai" | "script"; token?: string;
              topics: string[]; WebSocketImpl?: typeof WebSocket; retryMaxMs?: number });
  start(): void;                       // つなぐ。切れたら 1, 2, 4 … 最大 retryMaxMs(10000) ms でつなぎ直す
  stop(): void;
  call<M extends keyof Methods>(method: M, params?: Methods[M]["params"]): Promise<any>;  // 未接続なら即 reject
  on(topic: string, fn: (data: any) => void): () => void;
  onLink(fn: (state: LinkState, hello?: any) => void): () => void;   // open のとき hello の結果を渡す
}
```
- `Methods` は `host/api/generated/fprobe_api.ts` から import（`vite.config.ts` の `server.fs.allow` に `../api`）。
  session.* の追加メソッドも生成物に入っている。

- [ ] **Step 1: 試験**（偽の WebSocket: `sent` に送ったものを貯め、`receive(obj)` / `close()` を試験から呼ぶ）
  - open → hello（role human・token）→ subscribe(topics) の順に送り、両方の応答で `onLink("open", helloResult)`。
  - `call` は id で応答を対応付け、誤りは `RpcError(code)`。
  - 通知は `on(topic)` へ。
  - 切断で保留中の call は reject、`onLink("closed")`、1 s 後・次は 2 s 後につなぎ直す（fake timers）。
  - 未接続での `call` は即 reject。

### Task 3: 画面の状態（AppState）と整形

**Files:** Create `host/ui/src/lib/state.ts`, `src/lib/format.ts`, `tests/state.test.ts`, `tests/format.test.ts`

**Interfaces:**
- Consumes: Task 2 の `DaemonConnection`（試験では `call`/`on`/`onLink` を持つ偽物）
- Produces:
```ts
export interface Snapshot {
  link: LinkState; device: { link: string; address: string | null } | null;
  control: { paused: boolean; paused_by: string | null; held: number };
  clients: { id: number; name: string; role: string }[];
  target: Record<string, any> | null; probe: Record<string, any> | null; voltage: Record<string, any> | null;
  activity: ActivityEntry[]; hasOlder: boolean; error: string | null;
}
export class AppState {               // Svelte の store の約束を満たす
  constructor(conn: Pick<DaemonConnection, "call" | "on" | "onLink">);
  subscribe(fn: (s: Snapshot) => void): () => void;
  loadOlder(): Promise<void>;
  act(method: keyof Methods, params?: object): Promise<any>;   // 誤りは error に入れて投げ直さない
  get aiWorking(): boolean;           // 一時停止でなく、ai の利用者がいる
}
// format.ts
export function clock(iso: string): string;            // "12:01:03"
export function seconds(s: number | undefined): string; // "0.01 s" / "1.2 s"
export function outcome(e: ActivityEntry): string;     // 誤りなら誤り、でなければ結果の短い要約（80 字まで）
```
- [ ] **Step 1: 試験**
  - open で `session.status`・`probe.info`・`session.activity.list` を読み、device・control・clients・target・probe・activity が入る。
  - `probe.info` が誤り（機器の誤り）でも他は入り、error に文言。
  - activity 通知は seq の重複を除いて足し、並びは seq の小さい順。
  - `loadOlder` は `before = 最小の seq` で読み足し、空が返れば `hasOlder = false`。
  - 再接続で、読み直した最新の seq が手元の最大より小さい（デーモンの再起動）なら一覧を置き換える。
  - control・clients・target.state 通知が反映される。
  - `act` の誤りは error に入る。
- [ ] **Step 2: RED** → **Step 3: 実装** → **Step 4: GREEN**（`npm test`、`npm run check`）
