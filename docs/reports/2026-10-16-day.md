### 規模を減らすために行ったこと（機能・性能への影響）

1. **DDR3 のあるボードでは内蔵 BSRAM 版のロジアナを外した**（`LA_INTERNAL => false`）。
   深いバッファ版は同じ前段（サンプルレート・トリガ）を共用しており、深さ・読み出し速度で内蔵版を上回る。
   PC 側の `LogicAnalyzer` はケイパビリティ（LA_DEPTH = 0）を見て深いバッファへ自動で切り替える。
   DDR3 の無いボードでは内蔵版が使われる。制約: ロジアナ・イベント記録・メモリ試験が DDR3 を共用する。
2. **メモリ試験の期待値レジスタ（128 ビット）を削除**。期待値は番地と seed の xor なので比較の段で組合せで作る。
   機能・性能は同じ（mem_clk の Fmax は 102.6 → 108.5 MHz に向上）。
3. **イベントの待ち行列を 2 段 → 1 段**。受け付けは最短 2 周期に 1 件になるが、イベントは SWD 転送ごと
   （最速でも約 280 周期おき）なので実用上の差は無い。取りこぼしはハードウェアが数えて報告する（`lost`）。

## 熱

Gowin の電力見積もり（全信号 12.5% 反転の悲観的な前提）で総消費 0.87 W、推定ジャンクション温度 53 °C

FPGA に温度センサは無いため実測は外部（放射温度計等）で。密閉ケースに入れるならヒートシンクを推奨。

## 残課題

1. SWD 50 MHz（取り込みを次の立ち上がりの後へ遅らせる補償と自動較正。ターゲット側の上限も要確認）。
   25 MHz は達成（下記）。配線に GND を 1 本足すと信号品質の余裕が増す（ユーザーの作業）。
2. （済）DDR3 を FIFO として使う連続ストリーミング。
3. 多段トリガ、ターゲット CPU 自身のアクセスでのトリガ（DWT + SWO）。
4. CLS が 92% と高い。試した削減のうち、EP0 の受信バッファ（64 バイト）を分散 RAM にする案はレジスタを約 430 減らしたが
   CLS は減らず（LUT で律速、分散 RAM が LUT を使う）採用しなかった。削るなら LUT の多い所（DAP の転送・シーケンス処理、
   SWD / JTAG の PHY、ロジアナの符号器）を見直す。
5. **（解決）ULPI の DATA 出力の余裕が薄い（約 0.3 ns）** → ピンの隣への配置制約で余裕約 1.7 ns（Fmax 67 MHz）。以下は当時の記録: ULPI クロックの分配遅延が約 5.3 ns あり、出力レジスタがピンから離れて
   置かれると違反する。出力イネーブルが組み合わせ（not dir）なので出力レジスタを I/O ブロックに詰められない
   （I/O ブロックの入力レジスタは立ち下がり取り込みで占有）。違反すればビルドが失敗するので誤って出荷はしないが、
   機能追加のたびに配置次第で落ちうる。根本対策は ULPI の出力側の作り直し（出力イネーブルのレジスタ化と I/O ブロック化、
   または PLL によるクロックの遅延補償）。PHY モデルにバス衝突の検査を追加済み。
6. **（解決）書き込み直後の USB 列挙がまれに失敗する** → 原因: FPGA を書き込み直すと PHY のリセットが数 µs で、
   High-Speed で動いていたホストが切断に気づかず古いアドレスで要求を続けていた。起動時に 100 ms 切り離す
   （usb_reset の S_DETACH）ようにして、書き込み → 認識 15/15 回成功（毎回約 1.1 秒）。以下は当時の記録:
   （HIL で十数回に 1 回。デバイスは現れるが文字列記述子が読めないまま。
   書き込み直すと直る）。ULPI の余裕の薄さ（5.）か、PHY のリセットと列挙の順序に原因がありそう。HIL は 1 回だけ
   書き込み直して警告を残す（tests/hil/program.py）。ULPI の作り直しで合わせて調べる。
7. HIL 全件の中でだけ SWO の試験がまれに失敗する（4 MHz で No ACK。単独では 3/3 合格。昨夜も 1 回）。
   前の試験がターゲットに残す状態の影響とみている。
8. probe-rs で、切断時に CTRL/STAT を読むと読み値のパリティ異常がまれに出る（4〜25 MHz のどれでも 2〜5 割の頻度）。
   probe-rs が STM32F4 の手順でデバッグ電源を落とす要求（CTRL/STAT ← 0）をした後のポーリング中だけで、
   本来の操作の後なので結果には影響しない。電源切り替え中のターゲットの挙動とみているが、別のプローブと
   比べられていない（ST-LINK は使用禁止）。
