# Tang Nano 9K（fprobe_nano9k）の機能を 1 つずつ外した版（R13 の材料、2026-10-23）

今の fprobe_nano9k（クロストリガ・多段トリガ・故障注入・ロジアナのフィルタとパルス幅を外した構成）から、さらに機能を
1 つずつ外してビルドした（Gowin、--single = 配置の版を 1 つだけ）。GW1NR-9 の論理の上限は 8640。sys の制約は 54 MHz。
台本: scratchpad の r13_variants.py（ケイパビリティだけを替え、ソースは同じ）。

| 版 | 外したもの | 論理（LUT+ALU+SSRAM） | 結果 |
|---|---|---|---|
| base | なし（今の構成） | 8721（LUT 7739・ALU 868・SSRAM 19） | 容量を 81 超えて置けない |
| no_match | サンプラの値の一致（R21） | 8663 | 容量を 23 超えて置けない |
| no_manchester | SWO の Manchester の受信 | 8586 / 8640（100 %） | 配置で 57 LUT が置けない |
| no_sampler | DAP サンプラ（と値の一致） | 7648（89 %） | 置けて、Fmax 54.04 MHz で制約を満たす（余裕 0.07 %） |
| no_jtag | JTAG の PHY | 7683（89 %） | 置けるが Fmax 43.9 MHz で制約を満たさない |

事実:
- 今の nano9k の構成はサンプラの値の一致（R21）を持っている（ケイパビリティの既定が True。クロストリガが無い構成でも外れて
  いない）。外すと 58 減る。
- 1 つで収まって制約も満たすのはサンプラを外した版だけ（ただし余裕はほぼ無い）。JTAG を外すと収まるがタイミングを満たさない
  （最悪の経路はホストのリンクの mux → serial_link の scan と、CMSIS-DAP の packet → config）。
- どれを外すか（安価版の範囲）は利用者が決める。
