# J-Link 周辺のデバッグ・トレースアプリと fprobe の比較（2026-10-17）

目標「目指せ・追い越せ J-Link」に対して、J-Link と組で使われる主なアプリ（SEGGER 純正・各社 IDE・トレース専門・
オープンソース・最上位の TRACE32、日本で使われるテストポイント方式の DT10 / DT+）の機能と、fprobe の今を並べる。
fprobe の欄は 2026-10-17 夜の feat/f3-recording（F1〜F7 の部品・API と実機試験の結果）に基づく。他社の製品の欄は調べた範囲の知識で、細部は各社の
資料で要確認。UI・UX の比較は別の節（調査中、追記する）。

凡例: ◯ = ある（実機で確認） / ◇ = 部品はある・実機は未確認 / △ = 一部 / × = 無い。画面（GUI）はほぼ全項目で未対応（AI・API からのみ）

## 1. 止めて調べるデバッグ（Ozone・各社 IDE の領域）

| 機能 | 代表的なツール | fprobe | 今の状態 |
|---|---|---|---|
| SWD での接続・停止・再開・1 命令 | すべて | ◯ | 25 MHz。CMSIS-DAP v2 |
| JTAG での接続 | すべて | △ | Nucleo で確認（OpenOCD・pyOCD）。Pi 2 / Zero は配線待ち |
| 標準のツールから使う（GDB・OpenOCD・pyOCD・probe-rs） | J-Link GDB Server ほか | ◯ | 3 つとも実機試験あり |
| ハードのブレークポイント・ウォッチポイント | すべて | ◯ | 画面・MCP から |
| Flash 上の無制限のブレークポイント | J-Link（Unlimited Flash Breakpoints） | × | |
| ソースの表示・行でのブレークポイント | Ozone・IDE | ◯ | 画面のデバッガタブ |
| ソースの行単位のステップ（ステップイン・オーバー・アウト） | すべて | × | 1 命令のステップだけ |
| 逆アセンブル（ソースとの混在表示） | すべて | ◯ | API・MCP（画面なし） |
| メモリの表示・編集 | すべて | ◯ | 前回との差の印・シンボル名付き（画面なし） |
| 周辺レジスタを名前で表示・編集（SVD） | Ozone・Keil・IAR・Cortex-Debug | ◯ | 読むと変わるレジスタは既定で読まない（画面なし） |
| 変数: 構造体・ポインタ・ローカル変数・式の評価 | すべて | ◯ | C の式・列挙・ビットフィールド・書き込み（画面なし） |
| 呼び出し履歴 | すべて | ◯ | DWARF の CFI、例外のフレームを越える、段ごとの変数 |
| RTOS の認識（タスクの一覧・タスクごとの呼び出し履歴） | Ozone・Keil・IAR・Tracealyzer | ◇ | FreeRTOS・Zephyr（最小）。API に組み込み中 |
| マルチコア・Cortex-A / R・RISC-V | Ozone・TRACE32・Arm DS | × | Cortex-M のみ確認 |

## 4. 時間の流れで解析する（SystemView・Tracealyzer・DT+・TRACE32 の領域）

| 機能 | 代表的なツール | fprobe | 今の状態 |
|---|---|---|---|
| ロジアナ（内蔵・深いバッファ 128 MB・PC へ流し続ける） | 外付けロジアナ（Saleae 等）。J-Link 系には無い | ◯ | fprobe の強み |
| クロストリガ（波形でターゲットを止める等）・多段トリガ | TRACE32 の一部。J-Link 系には無い | ◯ | fprobe の強み |
| 共通の時計でのイベント記録（DAP の転送・UART・電圧） | TRACE32 の一部 | ◯ | 1 つの記録（検索・区間・書き出し）。画面は無い |
| 波形・デバッグの出来事・ログを 1 本の時間軸に並べて見る | Ozone（命令・電力）、DT+（トレース・アナログ・映像） | △ | 記録は 1 本の時間軸（実機確認）。それを見る画面が無い |
| RTOS のタスク・割り込みの時間軸 | SystemView・Tracealyzer | ◇ | 組み込み無し（サンプラで現在のタスクを読む）と、トレースフックの 2 方式。API に組み込み中 |
| 関数ごとの実行時間（プロファイル） | Ozone・IAR・Keil・Streamline・DT+ | ◇ | PC サンプリング（SWO・DWT_PCSR）、割り込みの時間、信頼区間。API に組み込み中 |
| 2 点間の処理時間・ばらつき | DT+・SystemView | ◯ | 記録の 2 条件の区間（統計・分布・外れ値の時刻） |
| コードカバレッジ | Ozone＋J-Trace・IAR・DT10（MC/DC まで） | △ | テストポイントで関数・C0・C1（実機確認）。PC サンプルの近似。MC/DC は無い |
| 命令トレース（ETM・全命令の記録） | J-Trace・TRACE32 | × | トレース端子と専用ハードが要る。手持ちのターゲットは要確認 |
| テストポイント方式（コードに出力を差し込み、外で時刻付きで記録） | DT10 / DT+ | △ | 自動挿入・差分の再挿入・解読・解析。2 線の GPIO を実機確認。並列・ITM は未確認。API は未 |
| 長時間の連続記録（日単位） | DT+Trace（最大 30 日） | △ | ロジアナの流し続ける捕捉はある。日単位の運用・検索は無い |
| プロトコルの解読（UART・SPI・I2C・SWD） | 外付けロジアナのソフト | ◇ | API あり、実機未確認 |
| 映像・アナログを同じ時間軸に | DT+Camera・DT+Analog | × | 電圧は 1 ms ごとの記録のみ |

## 7. まとめ

| 領域 | fprobe の到達度（目安） |
|---|---|
| 止めて調べるデバッグ | 基本はある。逆アセンブル・メモリ・SVD・構造体・ローカル変数・行ステップ・RTOS が無い |
| 書き込み | 外部ツール経由ではできる。画面と速さの確認が無い |
| 止めずに見る | ほぼ無い（RTT が無いのが大きい） |
| 時間の流れで解析する | 記録の部品（ロジアナ・イベント・共通の時計）は J-Link 系より強い。解析と表示がほぼ無い |
| 電源 | 電圧だけ |
| つながり方・自動化 | J-Link 系を上回る（AI・交代・Ethernet） |

- **fprobe だけの強み**: ロジアナとデバッガが同じ時計で一体、クロストリガ、AI と人の協働。
- **足りないものの大きな塊**:
  1. RTT（止めずに見る・ログ）。
  2. デバッガの画面の厚み（逆アセンブル・メモリ・SVD・変数・行ステップ）。
  3. 時間軸の解析（波形・イベント・ログ・RTOS・プロファイルを 1 本の時間軸に並べ、測る）。
  4. 電流。
- 「追い越す」方向: 3 は、J-Link 系では SystemView・Ozone・外付けロジアナに分かれていて一体ではない。DT+ が近い思想
  （テストポイント・アナログ・映像を同じ時間軸）だが、デバッガと一体ではない。fprobe は記録の部品を既に持つので、
  ここを画面と解析で仕上げるのが最も効く。

## 8. UI・UX の比較

各アプリの画面と使い勝手の調査は [2026-10-17-debug-ui-ux-survey.md](2026-10-17-debug-ui-ux-survey.md)。そこで見つかった
「優れたツールに共通する UI の型」に、fprobe の今の画面（作業・デバッガ・波形のタブ）を当てると次のとおり。

| UI の型（代表例） | fprobe の画面 | 今の状態 |
|---|---|---|
| 共通の時間軸に段を縦に積むタイムラインが中心（Ozone・IAR・SystemView・TRACE32） | × | 波形・デバッガ・記録が別々のタブ。時間軸は波形だけ |
| カーソル 3 種（選択・マウス位置・基準点）（Ozone） | △ | 波形にマウス位置のカーソルだけ。基準点・差分・選択カーソルが無い |
| ビューの双方向の連携（Tracealyzer のダブルクリック、Ozone の Sample Cursor） | △ | 止まると止まった行が開く、程度。記録・波形・ソースは連携しない |
| データからソースへ 1 クリック（IAR の Go To Source） | × | |
| 統計と生データの往復（Tracealyzer の Timing Metrics） | × | 統計が無い |
| 構造化された検索と、時間軸への印（Tracealyzer の Finder、TRACE32 の Trace.Find） | × | 記録の利用者での絞り込みだけ |
| キーボードで次/前へ（SystemView の F/B） | × | |
| ドッキング・配置の保存（Ozone・Tracealyzer） | × | 固定の配置 |
| GUI の操作と同じ働きのコマンド・API（Ozone・TRACE32） | ◯ | 画面と AI・スクリプトが同じ API |
| 能力に応じた表示と、使えない理由の明示 | △ | ケイパビリティで速度の選択肢等を出し分け。理由の表示は無い |
| 最初のビューまでの手順の短さ（Energy Profiler の 4 手順） | △ | ターゲット名と ELF の場所を手で入れる |
| 長い記録の扱い（間引き・ミニマップ・異常の印） | △ | 間引き（`la.view`）はある。縮図と印は無い |
| AI の行動を見る・一時停止・交代（どのツールにも無い） | ◯ | 作業タブ。ただし時間軸の段としては見えない |
| 調査の経緯を記録と結び付けて残す（どのツールにも無い） | × | |

UI・UX の到達度は機能より低い。「時間軸を中心にして、全部のビューをつなぐ」という、優れたツールの共通の骨格がまだ無い。
逆に言うと、fprobe は「デバッガとロジアナが同じ時刻を持つ」「AI と人が同じ画面を共有する」という、どのツールにも
無い部品を既に持つので、その骨格を作れば他に無い画面になる。
